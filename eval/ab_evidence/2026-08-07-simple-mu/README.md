# Blind A/B — F2.4 simple-mu retiming (2026-08-07)

Evidence for `c4b7382`: the simple-mu holdoff (20 hops → 200 ms) and its three
retention alphas (attack 0.3, hold 0.99, release 0.95, all authored at a 10 ms
hop), retimed together as one atomic change.

## Verdict: NO-GO. Freeze the whole batch.

Not because a bucket mean grazed the band. Because there are 51 case-level
regressions past the band, 19 of them past −0.1, the worst at **−0.349**, and a
control run establishes that these are real signal and not measurement noise.

| | Δecho ≤ −0.05 | Δecho ≤ −0.10 | Δdeg ≤ −0.05 | Δdeg ≤ −0.10 |
|---|---:|---:|---:|---:|
| C 16k/256 | 7 | 1 | 1 | 0 |
| C 16k/512 | 9 | 2 | 6 | 3 |
| Python 16k/256 | 9 | 3 | 4 | 3 |
| Python 16k/512 | 7 | 2 | 8 | 5 |
| **control** (1.1e-7 perturbation) | **0** | **0** | **0** | **0** |

Full per-case numbers: **[`AB_REPORT.md`](AB_REPORT.md)**, generated by
`eval/ab_report.py`.

### What the previous version of this file got wrong

1. *"Worst Δdeg anywhere is −0.034."* **−0.034 is a bucket mean.** The same
   JSONs contain case-level Δdeg of −0.349, −0.282, −0.232 and −0.207. Calling a
   mean "anywhere" turns an average into a claim about every case, and that is
   the claim a reviewer would use to decide the change is safe.
2. *"No other bucket moves."* True of means, false of cases: `FS_movement`
   (n=25) hides Δecho of −0.162, −0.152, −0.115; `DT_movement` (n=26) hides the
   four worst Δdeg in the run.
3. *"The two ports already disagreed on this clip before the change, so it sits
   on a decision boundary they fall off differently."* **Tested and falsified** —
   see "Python/C disagreement" below. It was a plausible story offered without a
   measurement.

Bucket means are near-neutral almost by construction when a change helps some
clips and hurts others, so a report built on means cannot fail in the way that
matters. Every number here is now generated per case by a tool.

## The control: these regressions are real

Before attributing anything, the per-case metric's noise floor was measured. A
worktree at `c4b7382` with `alpha_release` changed from `0.95f` to `0.9500001f`
— a **1.1e-7 relative** change, semantically null, but bit-changing (80 of 90
cases render differently) — was run through the identical harness.

```
worst Δecho  −0.001 (16k/256)   −0.008 (16k/512)
worst Δdeg   −0.000              −0.000
cases past the band: 0 of 180
```

So the metric is stable to two orders of magnitude below the effects reported
here. **The −0.349 and −0.257 are signal.** A "chaotic sensitivity" explanation
was hypothesised, tested, and refuted by this control.

Caveat on scope: the control bounds the metric's response to a *bit-level*
change. It does not bound its response to a larger but still semantically
neutral change. `noisefloor_control.diff` is the exact perturbation.

## Investigation of every case past −0.1

`eval/simple_mu_case_probe.py` runs one clip through the driver's own
`run_ours()` twice — all-frozen and all-retimed — and records the simple-mu
state trajectory plus target-free physical measures. 32 probes, 16 stems × 2
grids, in `probes/`.

### What this corpus can and cannot support

`wav/aec_challenge_blind` ships **mic and lpb only. There is no clean near-end
in any scenario** — not even `nearend_singletalk`, whose lpb sits ~3.7 dB below
its mic, i.e. the far end is playing there too. **SI-SDR and STOI are not
computable on this corpus.** Any figure presented as one would be scored against
a reference that still contains the echo the AEC exists to remove.

So the DT and NE degradations here cannot be physically decoupled. What is left
is a far-activity split, which needs no reference:

| | meaning |
|---|---|
| `d_near_db` | Output change on **far-inactive** hops. No echo is arriving, so everything in the mic is near end. Negative = the candidate removed near end the baseline kept. |
| `d_far_db` | Output change on **far-active** hops. On an FS clip the output *is* residual echo, so positive = worse. On DT the two are superimposed and this alone cannot separate them. |

…plus listening, which is a human step. It has **not** been done.

### Result: echo and deg regressions have completely different signatures

**Echo regressions are physically real and legible.**

```
HAxmF7v4…_farend_singletalk 16k/256   Δecho −0.257   d_far +0.45   LSD 5.45 dB   35% of frames changed >3 dB
ML4MF3Me…_farend_singletalk 16k/256   Δecho −0.162   d_far +1.65   LSD 2.99 dB   12%
3UAwzzOa…_farend_singletalk C 16k/512 Δecho −0.152   rms +1.73 dB  LSD 15.4 dB   50%
```

The mechanism for the worst one: at 16k/256, 200 ms is **25 hops against the
frozen 20**, so each arming holds mu frozen longer. The candidate takes 26 fewer
fresh onsets and 80 more hold hops, adapts less while the far end is active, and
leaves more residual echo. First divergence at hop 53 (424 ms) — during
convergence, not at some late event. The retiming is doing exactly what it was
specified to do, and this is its cost.

**Deg regressions have no energy-domain signature at all.**

```
Je6gJ7y1…_doubletalk   Δdeg −0.282   d_far −0.00   d_near −0.00   rms −0.00 dB   LSD 1.18 dB   2.0% of frames
JjCzlhn3…_doubletalk   Δdeg −0.223   d_far −0.27   d_near −0.00   rms −0.12 dB   LSD 1.25 dB   1.7%
QK70KpLu…_doubletalk   Δdeg −0.207   d_far +0.00   d_near −0.00   rms −0.00 dB   LSD 1.49 dB   2.6%
```

`d_near_db ≈ 0` across every one of them: **the candidate is not removing
near-end energy.** The intuitive "the filter freezes longer so the near end gets
crushed" story is not what the measurement shows.

What the changes are is *localised*: ~2% of frames, but 6–27 dB within those
frames. `listen_targets.txt` narrows all 11 deep-threshold deg cases to five
~30 ms windows each, and `listen/` carries 2-second excerpts (baseline and
candidate) around the worst window of the three largest. **Whether those
localised changes are audible is the open question, and it needs ears.**

## Python/C disagreement: unexplained

The two ports received an identical constant change. Their per-case responses
are essentially uncorrelated:

| grid | metric | corr(Python, C) | sign agreement |
|---|---|---:|---:|
| 16k/256 | Δecho | +0.018 | 53% |
| 16k/256 | Δdeg | +0.037 | 57% |
| 16k/512 | Δecho | −0.119 | 47% |
| 16k/512 | Δdeg | +0.141 | 53% |

Restricting to the cases where either port moved by more than 0.05 does not
help (corr −0.15 … +0.22, sign agreement 33–67%).

Two explanations were tested and both fail:

* **"These clips sit on a decision boundary."** Baseline port divergence on the
  flagged clips (LSD 6.06 dB median) is barely above the rest of the corpus
  (5.06 dB), and its correlation with the port disagreement is +0.18 for echo
  and −0.00 for deg. The flagged clips are not special.
* **"The per-case metric is chaotic."** Refuted by the control above.

The baselines are aligned (lag 0) and correlated 0.87–1.00 with RMS within
±0.6 dB, so this is not a harness misalignment either.

**No root cause found.** Acceptance criterion 4 is unmet, and it is the one that
should be resolved first: until it is, neither port's per-case result can be
trusted to represent the other, and "it passes in C" would not mean it passes in
production.

## The 2⁴ interaction matrix

All 16 settings of the four knobs, over the 16 flagged stems, at both grids
(`interaction_matrix_g{256,512}.json`, `interaction_matrix.txt`). Six points —
two extremes plus four singles — cannot separate an interaction from an
accident.

**Full retime is not Pareto-optimal.** At 16k/256, `1101`
(holdoff+attack+release, hold frozen) dominates `1111` on both far metrics and
ties on near:

```
mask   retimed                        far mean  far worst  near mean  near worst
1101   holdoff,attack,release           +0.016     +0.596     -0.185      -2.978
1111   holdoff,attack,hold,release      +0.105     +1.648     -0.206      -3.271
1100   holdoff,attack                   +0.194     +3.112     -0.185      -2.992
0001   release                          +0.023     +1.158     -0.003      -0.064
```

**The effects are strongly non-additive.** `1100` (far worst +3.112) is far
worse than either `1000` (+1.411) or `0100` (+1.192) alone — and *adding* the
remaining two constants to reach `1111` **improves** it to +1.648. A model in
which each constant contributes independently predicts none of this.

**And the ranking does not transfer between grids.** Spearman rank correlation
between the two grids' orderings: **+0.053**. The best non-trivial setting at
16k/256 (`1101`) ranks 6th at 16k/512; the best at 16k/512 (`0010`) ranks 8th at
16k/256; `1111` is 15th of 16 at one grid and 3rd at the other.

This is the empirical form of the objection that motivated the matrix: **the
mechanism is a state machine, not four independent EMAs.** The branch condition
is re-evaluated every hop, the counter only decrements on the hold branch, and
the holdoff length feeds back into the ratio trajectory that selects the branch.
Converting each constant correctly to wall clock does **not** make the state
machine wall-clock invariant, and the matrix shows the residual grid dependence
is larger than the effect being corrected.

Selection bias, stated: the cohort is the 16 flagged stems, chosen *because*
they regressed. These are worst-case numbers, not corpus means.

## Sample-size limits

A ≥25-case static far-end cohort was requested. **It cannot be built from the
data present**: `farend_singletalk` contains exactly **5** static stems, all
already in the 90-case manifest; `doubletalk` has **4**. The corpus is
overwhelmingly `_with_movement`.

The full 800-case AEC Challenge corpus is **not on disk** (`wav/aec_challenge/`
does not exist). So the release-grade run cannot be performed on this machine
and nothing in this directory substitutes for it. Fetching the full corpus is a
prerequisite for any ship decision and is a separate, authorised step.

## Acceptance criteria — all must hold

`c4b7382` and any successor stays NO-GO until every one is met:

| # | criterion | status |
|---|---|---|
| 1 | every bucket mean inside ±0.05, both ports, both 16 kHz grids | ✗ Python 16k/256 FS_static −0.052 |
| 2 | no unexplained audible regression in the worst-N per case | ✗ 19 cases past −0.1, none auditioned |
| 3 | every Δecho ≤ −0.1 and Δdeg ≤ −0.1 resolved by physical measurement or listening | partial — echo cases resolved physically; the 11 deg cases have no energy signature and need listening |
| 4 | root cause for the Python/C sign disagreement | ✗ two hypotheses tested and falsified; unexplained |
| 5 | both 16 kHz grids pass; 48 kHz has **native** 48 kHz release evidence | ✗ structural pass only |
| 6 | release-grade 800-case run on the full corpus | ✗ corpus not present |

Failing any of these the correct outcome is to **freeze the whole simple-mu
batch** and document it as a known grid-specific exception — not to keep a
partial retime. The matrix confirms the four are one mechanism: freezing three
and retiming one is measurably worse than either extreme at 16k/256.

## What is established and not in dispute

* The corpus exercises the mechanism. The branch census
  (`branch_census_g{256,512}.json`) covers all 90 cases; every branch fires
  heavily at both grids (16k/256: 9925 fresh onsets, 83095 ongoing, 121377 hold,
  166923 release over 381320 hops).
* It is not a no-op: 83/90 and 82/90 cases changed at the two C grids, worst
  |diff| 0.71 and 1.15 LSB.
* 200 ms → 12 hops on a 16 ms grid is deliberate ties-to-even, and the ports
  agree: C `lrintf()` and Python `round()` are both round-half-even.
* The four constants are one mechanism and must move together or not at all.
