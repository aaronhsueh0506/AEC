v3.10.4 → v3.21 → v3.22.4 (current shipped, 2026-06-03) → WebRTC AEC3 reference · same input/output, same v3.21 core pipeline. v3.22 did not restructure the architecture — it adds a post-filter policy layer + bug fixes on top of the v3.21 substrate. v3.22.4 adds three Pareto presets (gentle/balanced/aggressive) on a single floor knob — distinct from the old v3.10 40-knob 5-preset menu shown below.

v3.10.4 — legacy

Production 2026-05-05 → 2026-05-16

Five tuning presets (MILD / SOFT / BALANCED / AGGRESSIVE / MAXIMUM). Custom 9-stage ResFilter post-filter. ~40 RES knobs co-tuned per preset.

✗ Drawbacks of v3.10.4 — why we moved on

  • 9-stage ResFilter is Pareto-locked. Across v3.12 → v3.15 we ran 60+ ablations (S1–S11, F-E1 through F-E5, Arc M/G/F/T, Arc P/R/S-orth.A); the chain is at a ceiling — every ratio win on one bucket (FS / DT / NE) costs another bucket. Closed CANNOT-SHIP in batches.
  • 5-preset menu is co-tuned trap. Each preset wires ~40 RES knobs (over_sub_base / scale / dt_reduction / mask_*, etc.) that interact; touching a knob outside a full 800-case re-bench breaks the others. menu bloat
  • GCC-PHAT DelayEst is brittle. 1024 ms search range but no clock-drift detection; cohort-tail cases (qNvSMyU class, ~7/800) fall outside and the filter never converges. tail-7
  • No render-side analysis. Narrowband tonal renders (hum / fan / line noise) cause the refined filter to learn mic-as-echo, killing NE buckets (E0l0 / wJVP class).
  • Reverb tail collapsed into stage 1. One-tap exponential decay is a poor proxy for actual room reverb impulse responses.
  • No sub-band ERLE. Fullband-only ERLE drives the suppressor; can't selectively trust the filter in some bands while distrusting in others.
  • Filter convergence detector is a hard 10-frame > 5 dB ERLE latch. Permanently False on hard cases (9xjhi class) → R² collapses to nonlinear forever.

v3.21.0 — AEC3-aligned baseline (current shipped is v3.22.2, below)

Production from 2026-05-19 · superseded by v3.22.2 (policy + bug-fix layer on this same architecture)

Single BALANCED preset (5 overrides). Reference-path HPF retired. AEC3-aligned _aec3_post chain (StationarityEstimator + AecState + ResidualEchoEstimator + SuppressionGain + comfort noise + OLA) replaces the 9-stage ResFilter.

✓ What v3.21 fixed vs v3.10.4

  • Retired the 9-stage ResFilter → AEC3-aligned _aec3_post chain (StationarityEstimator + AecState + ResidualEchoEstimator + SuppressionGain + CNG + OLA). DT/NE deg now beats AEC3 reference by ≥ 0.52 / 0.60.
  • Single BALANCED preset. 5 overrides only. No co-tuning trap.
  • AEC3-aligned delay subsystem — matched filter + lag aggregator + clock-drift detector + render-delay controller (replaces GCC-PHAT).
  • RenderSignalAnalyzer — per-bin tonal mask + poor_signal_excitation freezes the refined filter on bad render frames (fixes E0l0 / wJVP class NE outliers).
  • AecState ADT over 12 sub-analyzers → multi-gate usable_linear_estimate replaces the brittle 10-frame ERLE latch.
  • Sub-band ERLE drives SuppressionGain ERLE-divide refinement, AEC3-style.
  • ReverbModel — per-bin tail across the impulse response (decay + frequency response), replacing the one-tap exponential.
  • Shadow filter switched to NLMS (PBFDAF) — AEC3 coarse-filter role; faster tracker that survives echo path changes.
  • FilterMisadjustmentEstimator + ScaleFilter — long-term echo/error drift triggers W rescale.
  • Reference-path HPF retired (v3.19 verdict): −0.04 nores deg with no echo gain.
  • Byte-equal regression gate — 25 representative cases (5 / bucket at echo percentiles 0/25/50/75/100), md5-compared per cleanup commit.
  • ~5 500 Python LOC removed, ~32 k doc lines pruned, 0 algorithm-output regression.

⚠ Known issues / gaps still in v3.21

  • TransparentMode disabled. Our AecStateConfig.enable_transparent_mode = False: requires AEC3's SubtractorOutputAnalyzer to feed a per-frame any_filter_converged pulse; legacy FilterConvergenceAnalyzer stays at False on hard cases like 9xjhi, so TM would falsely activate after ~6 s of strong render and kill usable_linear. Port pending. v3.21+ TODO
  • C port lag. The C implementation at c_impl/ still ships the legacy ResFilter chain. v3.21.x C-port arc needs to mirror Python's AEC3 chain. c_impl debt
  • Substrate flags partially retained. R10 follow-up deferred: arc_m_t_gated_enabled gates were removed but a few unused config fields remain in scope-creep edge cases (e.g. use_diverged_streak_ema, epc_r_reset_enabled, plan_b_dt_per_bin_gamma). Default-OFF; no audio impact. tech debt
  • OLA delay accounting. The AEC3 chain has a ~64-sample (4 ms) algorithmic delay from sqrt-Hann OLA. Already fixed in v3.21 anchor commit 3aadd2d (lag-corrected output limiter), but consumers downstream of aec.process() should be aware of the per-frame latency. documented
  • Volterra NL inverse filter not started. v3.13 E5 closure identified non-linear (loudspeaker distortion) as the remaining FS/DT ceiling; v3.14+ Volterra arc designed but not implemented.
  • NN joint NR + RES + Dereverb arc not started. Out of scope for v3.21 (DSP-only release per project memory).
  • p52_regime_classifier.py only used in tests. Module ships but is consumed only by test_p52_regime.py; if you don't need the regime trace, drop both. audit
  • Legacy FilterConvergenceAnalyzer still wired. AecState uses the AEC3-aligned multi-gate, but the legacy 10-frame ERLE latch object is still maintained on self._convergence for backward-compat property reads.

WebRTC AEC3 — reference

Chromium modules/audio_processing/aec3/

No preset menu — single EchoCanceller3Config struct with Field-Trial overrides. The canonical reference our _aec3_post chain mirrors.

⚠ Known issues / quirks in WebRTC AEC3 itself

  • TransparentMode false-activation. After ~6 s of strong render with no near-end speech, the SubtractorOutputAnalyzer / FilterAnalyzer combo declares the room transparent and the suppressor passes mic through — even when echo is still present. Documented inside the C++ code (aec_state.cc comments); WebRTC ships it default-ON anyway because it helps the common Chromium use-case. Our v3.21 disables it (see v3.21 issues card above).
  • Strict refined-filter convergence detector. FilterAnalyzer::Update requires 10 consecutive blocks > 5 dB ERLE to assert consistent_estimate. On hard cases (deep DT or low-coupling rooms with reverb), this never asserts → AecState's downstream gates are stuck in their fallback paths. Known WebRTC limitation, no upstream fix.
  • Sub-band ERLE EMA can lock high during heavy DT. The asymmetric EMA biases towards higher ERLE; in heavy DT segments the per-band ERLE estimate stays optimistic and SuppressionGain over-suppresses NE.
  • Reverb decay estimator is loosely identified. The decay coefficient comes from a one-tap fit to echo_path_estimate tail; real rooms have multi-rate decay (early reflections vs late tail) that the model collapses.
  • OLA in suppression_filter.cc is mathematically clean. kFftLength=128, hop=64 (kFftLengthBy2), sqrt-Hanning analysis × sqrt-Hanning synthesis = Hann at 50 % overlap → sum-to-one reconstruction. Standard textbook setup — no known OLA-specific defect. The 64-sample (4 ms) algorithmic delay it introduces is inherent to the design, not a bug.
  • Coarse filter (NLMS shadow) has no gain control. μ is fixed at 0.5 (kCoarseFilterStepSize). On near-end-heavy frames the coarse filter can drift faster than the refined filter; AEC3 mitigates with poor_coarse_filter_counter but the trigger is conservative.
  • EchoPathChange detection is energy-based. EchoPathChangeDetector looks at far-energy step changes; can't distinguish a real path change from a microphone gain change (handset → speakerphone). Mostly benign because the response is the same (filter reset) but the event log conflates them.
  • EchoCanceller3Config is a 150-field struct. Field-Trial overrides spread across Chromium make production tuning hard to audit; no preset menu (unlike our pre-v3.21 design — though we just retired ours too).

v3.21 vs WebRTC AEC3 — current alignment + remaining gaps

v3.21 ships an AEC3-aligned but not bit-equal port. Same block-level structure, mostly the same algorithm, but several detail choices differ. The closer this list gets to empty, the closer we are to a 1:1 port.

✓ Already aligned with AEC3

  • Block / FFT / hop rates (64 / 128 / 64).
  • Refined Kalman filter + NLMS coarse-filter pairing.
  • EchoPathDelayEstimator — matched filter + lag aggregator + clock-drift.
  • RenderSignalAnalyzer — narrowband tonal mask + poor_signal_excitation.
  • AecState ADT seam over sub-analyzers (we have 12, AEC3 has 11 — close).
  • ResidualEchoEstimator linear / render-based 2-path + ReverbModel tail.
  • SuppressionGain Wiener + over-estimation.
  • ComfortNoiseGenerator = per-bin PSD EMA × sqrt(1 − G²).
  • SuppressionFilter OLA with sqrt-Hann analysis × sqrt-Hann synthesis.
  • StationarityEstimator + FilterAnalyzer + FilteringQualityAnalyzer.

⚠ Where v3.21 still differs from AEC3

  • No TransparentMode. AEC3 has it (default ON in Chromium); we disabled because we lack SubtractorOutputAnalyzer — see future work below.
  • No NearendDetector. AEC3's subband NE detector feeds SuppressionGain mode switching; our v3.18 D.1 substrate closed CANNOT-SHIP, so we don't have an equivalent live consumer.
  • No EchoAudibility module. AEC3 computes per-bin audibility from JND-weighted PSD ratios; we use a simpler spectral floor.
  • SuppressionGain over-estimation differs. AEC3 has a four-mode HighFrequencySuppressionConfig + DominantNearendConfig with mode-switched coefficients; ours has a smaller subset and the high-frequency mode tuning is not fully aligned.
  • Reverb decay estimator is partial. We have ReverbDecayEstimator + ReverbFrequencyResponse but the estimation gate is simpler than AEC3's adaptive tail-length controller.
  • FilterMisadjustmentEstimator is ours. AEC3 has a different ScaleFilter design (per-block scale ratios); we use a single fullband ratio with asymmetric EMA. Same goal, different math.
  • PathChangeRegimeHandler is ours. AEC3 handles echo-path-change via Subtractor::HandleEchoPathChange + AecState's full_reset cascade. Our regime handler bundles those decisions with shadow-copy logic that AEC3 doesn't have.
  • Coarse-filter step size. AEC3 uses 0.5; we expose shadow_mu_nlms defaulting to 0.5 but our coarse-filter freeze logic (poor_coarse_filter_counter) is partial.

→ v3.21+ port targets (would shrink the diff)

Note: the shipped v3.22 line did not pursue these AEC3 ports — it took the orthogonal post-filter policy route instead (split min-gain floor + per-bin near-end blend + delay-acquire guard, see the v3.22.2 section above). These remain open AEC3-alignment targets.

  • Port NearendDetector + mode-switched SuppressionGain. Pair with retry of the v3.18 D.1 subband-NE substrate that closed CANNOT-SHIP — the new wiring goes through SuppressionGain directly instead of ResFilter. v3.22
  • Port EchoAudibility. JND-weighted per-bin gain floor; should improve NE-heavy buckets without echo regression. v3.22
  • Align SuppressionGain over-estimation. Bring the 4-mode HighFrequency + DominantNearend tuning into our suppression_gain.py. v3.22

→ Future arcs (beyond AEC3 alignment)

v3.21.6 → v3.21.6-alignment — two production-blocking bugs fixed

Cycle 2026-05-22 → 2026-05-27 · 10 alignment commits, byte-equal broken intentionally · followed by 12 cleanup commits (audio-zero)

The v3.21.6 baseline shipped with two user-audible defects on the internal DT cohort: a low-band nores artifact (linear filter over-estimating echo in 0–500 Hz, producing a grid/fan pattern in the residual) and a high-band painted-black HF (residual chain over-suppressing > 4 kHz during DT, ratio of reverb-to-direct R² spiking to 10⁶). The alignment cycle traced both to AEC3-port fidelity gaps and shipped 10 strict-AEC3 fixes; the cleanup cycle then removed all dev-time substrate without touching audio output.

Bug 1 — nores LF artifact (linear-filter over-estimation)

Symptom: ours_nores.wav showed periodic LF energy bursts on FS_static cases (e.g. 9xjhi…_farend_singletalk) — the linear filter was over-predicting echo in 0–500 Hz, so the residual carried inverted-phase energy instead of cancelling cleanly.

Root cause (PBFDKF refined-filter weight-update parity):

  • RefinedFilterUpdateGain denominator used X²_latest (current hop only) instead of AEC3's SpectralSum = Σₚ|X_buf[p]|² → LF bins where energy is spread across history got under-estimated denom → μ blew up → W grew with wrong phase.
  • Per-bin H_error refresh missing (AEC3 cc:128-138) — scalar fullband leakage couldn't disambiguate per-bin filter health.
  • H_error ceiling clipped to 100 (legacy int16-derived) vs AEC3's kHErrorCeiling = 2.0 in float — 40 %+ of steady-state frames saturated against the wrong ceiling.
  • Refined-filter noise gate constant was 27509562 (suppression-path value) instead of AEC3's filter-update 20075344 → 1.37× too-tight gate, bins where AEC3 would update W were hard-zeroed.
  • μ denominator's n_part·E² term used smoothed _error_psd (α = 0.95, ~200 ms lag) instead of AEC3's instantaneous |error_spec|².

Fixes shipped: 5 default-ON flags (use_partition_summed_x2_for_h_error_gain, use_per_bin_h_error_refresh, use_aec3_h_error_ceil, use_aec3_filter_noise_gate_power, use_current_e2_refined_in_h_error_denominator) + matching shadow PBFDAF parity (A.1–A.5) + AEC3-strict EPC handling chain. Now all hard-coded; legacy branches deleted in cleanup.

Bug 2 — painted-black HF (residual chain over-suppression)

Symptom: on the internal DT case, > 4 kHz bins showed gain_hf_median < 0.1 (painted black on the spectrogram) for 24.3 % of frames; reverb-to-direct R² ratio median was 6.2 with p95 = 170, max 1.2×10⁴. Symptoms read as "HF deficit" — speech sounded thin / muffled during DT.

Root cause (residual reverb chain + back-end alignment):

  • Reverb-render-history bug: ReverbModel was being fed the current render PSD instead of the render block from N + 1 partitions ago (AEC3 residual_echo_estimator.cc:367-376 reads the delayed slot). Direct-path R² and reverb-tail R² were therefore being computed from the same time-aligned render → reverb mass got double-counted against direct in HF bins where direct > 0.
  • RFR neighbour window: our ReverbFrequencyResponse used a ±4-bin neighbour max (matching AEC3's physical 125 Hz width at fft = 128). At our fft = 512 (31.25 Hz/bin), ±4 bins = 125 Hz × 4 / 4 = wider in spectral resolution. Sparse HF energy got spread across the wider window → HF reverb inflated.
  • ReverbConfig defaults: decay = 0.85, mild_decay_scale = 0.5, use_adaptive_decay = True diverged from AEC3 production defaults (0.83 / 1.0 / False per ep_strength.default_len = 0.83).
  • Audibility band boundaries: v3.21.5 used 94 Hz / 219 Hz LF / MF anchors (legacy from a 65-bin port). AEC3 production at fft = 128 uses 375 Hz / 875 Hz — directly transferable to our 257-bin grid.
  • HF cap anchor: 4000 Hz cap was clamping bins WIDER than AEC3's 2000 Hz, 1-bin (31.25 Hz, not 125 Hz) anchor → wide-band HF damping on DT.
  • Comfort noise generator: legacy CN used error_psd as noise source + a 0.4 fixed scale on the lowest band; AEC3 uses raw mic Y² + sqrt(1 − G²) with no 0.4 scale + an LCG + LUT phase generator → audible HF colour mismatch during NE-only stretches.
  • Stationarity window: hard-coded 13 AEC3 blocks = 52 ms; at our 10 ms hop this should be 5 hops, but the literal-port treated it as 13 hops = 130 ms. Same for hangover (12 → should be 5).
  • OLA synthesis window: numpy np.hanning denom is N − 1; MATLAB-canonical Hann uses N, producing slightly mismatched overlap-add (visible in spectrogram tile boundaries).

Fixes shipped (10 commits): reverb history ring buffer; ±4-bin → strict ±1-bin neighbour max; AEC3-strict ReverbConfig defaults; audibility band rescale (375 / 875 Hz); HF cap anchor 2000 Hz with 1-bin width; AEC3-strict 3-state N2 estimator + sqrt(1 − G²) + LCG/LUT CNG; MATLAB-canonical sqrt-Hann OLA; stationarity window auto-rescales via blocks_to_hops(); detect_pre_echo default True (AEC3 strict); FilterPlateauDetector moved to opt-in (Python-only safety net, no AEC3 equivalent).

v3.22.2 — current shipped (on the v3.21 substrate)

Production from 2026-06-02 · __version__ = 3.22.2

v3.22 is built on top of v3.21 — the core pipeline is unchanged (HPF → Saturation → DelayEst → PBFDKF + shadow PBFDAF → AEC3-post = StationarityEstimator + AecState + ResidualEchoEstimator + SuppressionGain + CNG + OLA). v3.22 did not restructure the architecture; it added a post-filter policy layer (frequency-selective near-end protection + split min-gain floor) plus a stack of default-ON bug fixes / coordinate-consistency corrections. The flowchart is the v3.21 diagram above; the changes below all live inside the SuppressionGain / ResidualEchoEstimator / ERLE blocks and the delay-acquire guard.

v3.22.0 — split min-gain floor + default-ON correction stack

  • Split min-gain floor (far-active vs far-silent), default ON. The single broadband suppression-gain floor is split into two operating points keyed on far-end activity → caps DT near-end over-suppression without giving up FS echo depth. This is the core v3.22 policy lever.
  • E1 — ERLE coordinate consistency. Y²/E² windowed capture aligned so the ERLE numerator/denominator share the same time-domain capture coordinate (fixes a frame-skew that under-credited the linear filter).
  • erle_render_x2_psd_scale — reverb-model revival. Restores the missing _PSD_SCALE on _x2_reverb_for_erle so the reverb model contributes to ERLE instead of being silently dead.
  • E2 — raw-capture output base. When the linear estimate is unusable, the output base falls back to the raw capture (instead of a degenerate residual) → removes the cold-start / non-converged X² wipe artifact.
  • D3 — soft near-end tuning blend. Sigmoid ENR-driven blend that softens the near-end vs echo gain decision instead of a hard switch.
  • L1 — Kuech–Kellermann 2nd-order nonlinear residual. Adds a 2nd-order nonlinear term to the residual echo estimate (loudspeaker non-linearity), feeding ResidualEchoEstimator.
  • C′ — coherence ERLE gate. Coherence-based gate on the ERLE update path.

v3.22.1 — delay-acquire phantom-mislock guard

  • delay_acquire_protect_converged, default ON. Rejects a spurious late first delay-acquisition when the filter is already cancelling — i.e. when a phantom late lag would otherwise displace a good converged alignment. Lives in the EchoPathDelayEstimator acquire path; no change to the steady-state tracker.

v3.22.2 — per-bin near-end blend + deeper far-active floor (current BALANCED)

  • soft_nearend_blend_per_bin, default ON. The D3 near-end tuning blend goes frequency-selective (per-bin) instead of broadband. Near-end protection now applies only in the bins that carry near-end speech.
  • far-active min-gain floor lowered −22 → −28 dB. Because the per-bin blend isolates near-end protection, the deeper far-active floor can suppress more echo without the broadband DT near-end cost the deeper floor would otherwise have caused. This is the v3.22.2 net win: more echo cancellation at no DT-deg penalty.

What stayed exactly the same as v3.21

  • Front-end (HPF mic-only, Saturation, EchoPathDelayEstimator) — unchanged.
  • Linear filter (PBFDKF refined + shadow PBFDAF/NLMS + PathChangeRegimeHandler) — unchanged.
  • AEC3-post block topology (StationarityEstimator → AecState → ResidualEchoEstimator → SuppressionGain → CNG → OLA) — unchanged; v3.22 tunes the policy inside these blocks, not their wiring.
  • Single BALANCED preset; _ours_nores.wav bypass tap; byte-equal regression harness — all unchanged.
