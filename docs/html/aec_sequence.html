AEC 流程時序圖 — AEC/c_impl

概要

本頁用 <pre> ASCII 時序圖畫 AEC 庫的呼叫順序。lifeline:Application(呼叫端)、Aec(aec.c)、audiolib(FFT／HPF 等共用庫)、下游 stage(NR／合成,屬 Audio_ALG 與 audiolib,非 AEC 庫)。AEC 庫是純 DSP:沒有 NN runtime／加速器 lifeline,跨 hop 的 state 全在 Aec 內,呼叫端不需另存。箭頭上的名稱都是真實函式;aec_* 的 static 函式為 aec.c 內部步驟(列出是為了對照順序,不是 API)。用法與範例見 aec_usage。

 |                                                |                                                 |
 |- aec_process(aec, mic, ref, out) ------------->|                                                 |

 |< out[hop] -------------------------------------|                                                 |

順序取自 aec.c 的 aec_process_core(shadow 先於 main)。enable_res = 0 且 return_res_context = 0 時整個 post 區塊跳過,final_out 為線性殘差。

3. 穩態一個 hop:頻域 seam 與下游 stage

 Application                                      Aec                                     下游 NR / NN                    AcIstft (audiolib)
 |                                                |                                       |                             |
 |- aec_process_context(mic, ref) --------------->|                                       |                             | 同 §2,但不 memcpy 到 out
 |- aec_get_res_context(&ctx) ------------------->|                                       |                             |
 |< error_spec / near_spec / r2 / cn / res_gain --|                                       |                             |
 |- aec_get_linear_context(&lin) ---------------->|                                       |                             |
 |< aligned_far_hop / delay_state / generation ---|                                       |                             |
 | (以上指標借自 AEC 的 per-hop buffer,下一次 process/reset 前有效)
 |- E, R2, CN, g_res -------------------------------------------------------------------->|                             |
 |                                                |                                       | NR 增益 g_nr(r2 / 32768^2 併入噪音底)
 |< g_nr ---------------------------------------------------------------------------------|                             |
 | g = min(g_nr, g_res);P = E * g;aec_cng_fill(&rng, P, cn, g_res, g_nr, floor, n)
 |- ac_istft_push(P) -------------------------------------------------------------------------------------------------->|
 |< out[hop] -----------------------------------------------------------------------------------------------------------|

單聲道實際串接見 Audio_ALG pipelines/mono_aec_nr_res/main.c。AEC 端必須 enable_res = 0 且 return_res_context = 1。aec_process、aec_process_context、aec_process_context_shared_far_from 推進相同的內部 state,可在同一實例上交錯。單聲道的 RES 增益(res_gain)由 post 區塊在 AEC 的呼叫內算出,不另建 AecRes;純 AEC 的範例可以直接呼叫 aec_process(),RES 與最後的合成都在同一個呼叫內完成。

4. 被拒絕／錯誤路徑

 Application                                                  Aec
 |                                                            |
 |- aec_get_mem_size(&bad_cfg) ------------------------------>|
 |< 0 --------------------------------------------------------| 不是負值;務必檢查 == 0
 |- aec_init(unaligned_or_small_pool, ...) ------------------>|
 |< NULL -----------------------------------------------------| 未 16-byte 對齊 / mem_size < need / cfg 無效:寫入 pool 之前就拒絕
 |- aec_create(&aec, &bad_cfg) ------------------------------>|
 |< -1 -------------------------------------------------------| cfg 無效或 malloc 失敗
 |- aec_process(...) ---------------------------------------->|
 |< void -----------------------------------------------------| 沒有錯誤路徑:所有可偵測的錯在建立階段擋下
 |- aec_set_level(aec, bad_level | bad_ramp) -------------->|
 |< -1 -------------------------------------------------------| NULL / enum 外 / ramp_ms 非有限或不在 [0, 60000];什麼都沒寫
 |- aec_set_level(spatial_linear_context lane, ...) -------->|
 |< 0 --------------------------------------------------------| 回 0 但依構造無效:該 lane 不走抑制增益路徑
 |- aec_apply_external_realign(aec, d) ---------------------->|
 |< -1 -------------------------------------------------------| NULL 或 delay_mode != EXTERNAL_ALIGNED(d == 0 回 0)
 |- aec_get_res_context(aec, NULL) -------------------------->|
 |< (no-op) --------------------------------------------------| NULL 實例或 NULL 輸出:你的結構不被寫入
 |- aec_reset(NULL) / aec_process(NULL, ...) ---------------->|
 |                                                            | NULL 會 crash(無檢查)
aec_set_level 對 spatial_linear_context lane 的結果依構造無效,但不是回 -1(本機實測回 0):它只寫該 lane 的 cfg 與其 SuppressionGain 目標,而該 lane 從不計算增益。需要改強度時,對那個融合後共用的 AecRes 呼叫 aec_res_set_level()。

Audio_ALG 的 4ch 流程層 mcab 只管共用 delay、四條由應用注入的 Aec lane 與 mcab_fuse()(g_res_ctx = NULL),不含 RES,也不含波束成形;RES 由應用在 mcab 之後用 AecRes 自己建立、每 hop 在 fuse 之後呼叫(aec_res_process(),輸入由 mcab_sample_res_input() 組出)。上圖是直接驅動各 lane 的寫法;mcab 加應用的完整呼叫序列(mcab／AecRes／NR／ISTFT 四條生命線)見 aec_res §2.3,流程的時序見 pipeline_4ch。

7. 泳道圖:啟動期與延遲(橫軸 hop)

以 16 kHz／256(hop 128 = 8 ms)為例;其他格點把 hop 換成 256／512 即可。

hop →               1        2      ...     13       14       15     ...
------------------------------------------------------------------------------------
caller         mic,ref -> aec_process / aec_process_context -> out(enable_res = 1 時晚 1 hop)
------------------------------------------------------------------------------------
EXTERNAL       LOCKED(delay_samples = 0,confidence 1.0,從第 1 個 hop 起)
FIXED d=1600   UNLOCKED  UNLOCKED  ...  UNLOCKED  LOCKED   LOCKED   ...
               (前 ceil(d / hop) = 13 個 hop:ref ring 尚未填到 d + hop 個樣本,
                aligned_far_hop 是未補償的 raw far)
MATCHED        UNLOCKED(delay_samples = -1) ......... 擷取後該 hop 回報 CHANGED 一次,再 LOCKED
               擷取條件:n_updates >= 3 且延遲在 ring 容量內(aec.c aec_align_reference)
------------------------------------------------------------------------------------
線性濾波器     warmup_frames(authored 100 x 10 ms;16k/256 內部重定時為 125 hop,約 1 s)內較積極收斂
RES / post     enable_res = 1:輸出比線性路徑晚 1 hop(WOLA);enable_res = 0:0 延遲
seam 讀者      ctx / lin 有效到「下一次任何 process 或 reset 呼叫」
格點hopenable_res = 1 演算法延遲(脈衝實測,手冊 §3)MATCHED 可擷取上限
8 kHz／256(legacy)12816.000 ms1216 ms
16 kHz／2561288.000 ms608 ms
16 kHz／51225616.000 ms608 ms
48 kHz／102451210.667 ms608 ms

FIXED 的 13 個 UNLOCKED hop 與第 14 個 hop 起 LOCKED,是在暫存複本實跑 aec_get_linear_context 的結果(16k/256、fixed_delay_samples = 1600)。MATCHED 的實際擷取所需 hop 數隨訊號而定:待量測。可靠搜尋範圍 509 ms(delay_num_filters = 5)與 608 ms 幾何全 span 是兩種定義,見 AEC API §4 與 AEC/docs/delay_estimator_design_zh_TW.md。
