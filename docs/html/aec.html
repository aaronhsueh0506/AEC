AEC C library(單聲道)— AEC/c_impl

概要

單聲道 PBFDKF 回音消除器的 float32 C 實作(Python aec.py 為演算法規格)。一個 hop 的處理鏈:mic 端 HPF → 飽和偵測 → AEC3 matched-filter 延遲估計 + 參考訊號 ring buffer 對齊 → PBFDAF shadow / PBFDKF main 線性濾波 → AEC3 post(殘留回音抑制 RES + CNG)。全部 state 收在單一 Aec struct(caller pool 或單一 heap arena),process 熱路徑零 malloc(make test-zero-heap 實測 50 個 init/process/reset/destroy 週期 allocator 呼叫為 0)。heap 與 caller-pool 兩條建構路徑輸出逐位元相同(test_static_aec 驗證 byte-equal)。

沒有任何 NN/NPU 成分:本函式庫是純 DSP,跨 hop 的 state 全部由 C struct 保存,host 不需另存任何 state。AecResContext / AecLinearContext 兩個 seam 是外接 NN 後級(RES/NR)時的接點,見 AEC/docs/nn_integration_interface.md。

API 用法

下面是摘要;完整可編譯範例與錯誤處理見 aec_usage。

#include "aec.h"

AecConfig cfg;
aec_config_from_level(&cfg, AEC_LEVEL_BALANCED, 16000);
/* 可選:cfg.fft_size = 512;  10ms-authored 常數在建構時(aec_carve)
 * 才對最終 hop 重定時,所以覆寫 fft_size 是安全的 */

/* A. caller pool(嵌入式建議;零 heap) */
size_t bytes = aec_get_mem_size(&cfg);          /* 回 0 = config 無效 */
Aec* a = aec_init(pool, bytes, &cfg);            /* pool 需 16-byte 對齊 */

/* B. heap(單一 malloc arena) */
Aec aec;                                          /* struct 由呼叫端持有 */
if (aec_create(&aec, &cfg) != 0) { /* 失敗 */ }

int hop = aec_hop_size(a);
for (每個 hop) {
    aec_process(a, mic, ref, out);   /* 各恰好 hop 個 float32 樣本 */
}
aec_destroy(a);   /* aec_init 實例不釋放記憶體;pool 由呼叫端釋放 */

Delay mode(cfg.delay_mode,init 時決定、instance 存活期間 immutable,三態互斥,非法組合被 aec_validate_config() 拒絕而非 clamp):

AEC_DELAY_MATCHED(預設)delay_num_filters = 1–5;fixed_delay_samples 須為 −1AEC3 matched-filter 線上估計延遲,參考環形緩衝套用
AEC_DELAY_FIXEDfixed_delay_samples ≥ 0;delay_num_filters 須維持 5不建 estimator;配置剛好 fixed_delay_samples + hop_size 的環形緩衝套用固定延遲

三個 process 進入點推進完全相同的內部 state(都經 aec_process_core()),只差結果怎麼交付,可在同一實例上自由交錯、不需 reset:

進入點用途

Level(強度軸;Python 稱 preset,C level == Python preset):mild／balanced 只差 min_gain_floor_far_active_db = -20／-28 dB;aggressive 另把 min_gain_floor_dt_db(double-talk 時改用的地板)從 -20 深化到 -30 dB(否則三個 level 在 DT 保護觸發時會蓋回同一個 -20,聽不出強度差);第四個 no_floor(min_gain_split_floor_enabled = 0)整個拿掉地板機制,是軸上最深的操作點。四個 level 的數值表見 外部參數。

執行期改強度:aec_set_level(a, level, ramp_ms) 可在 running 實例上重新指定 level(濾波器、延遲鎖定與平滑歷史都不動)。ramp_ms 只管 far-active 地板(dB 線性走位,[0, 60000]);DT 地板與 no_floor 旗標立即套用;回 0 或 -1(-1 時什麼都沒寫);hop 之間呼叫、非 thread-safe;以 spatial_linear_context 建的 lane 對它為無效操作,四麥克風產品改對應用自己建立的共用 AecRes 呼叫 aec_res_set_level()(Audio_ALG 的 4ch mcab flow 不含 RES,見 aec_res §2.3)。ramp 語意與量測前必須知道的兩件事見 aec_detail,範例見 aec_usage。

AecResContext seam(aec_get_res_context(),頻域,外接 NR/RES 用):error_spec = formed 線性輸出的 50%-overlap periodic-sqrt-Hann STFT E(f)(音訊尺度);echo_spec 為對應回音估計、near_spec = error_spec + echo_spec;res_gain = AEC3 SuppressionGain G_res(f) ∈ [0,1];r2(殘留回音 PSD)與 comfort_noise(CNG N²)為 int16² 尺度(除以 32768² 得 |E|² 音訊功率尺度)。頻域欄位僅在 enable_res=1 或 return_res_context=1 時非 NULL;spatial_linear_context=1 時 res_gain 恆為 NULL(該 lane 的 G_res 根本沒算,NULL 表示「未計算」而非「全抑制」)。分析 seam 與渲染底座:formed_hop／error_spec／echo_spec／near_spec 在任何模式(aec_process()、context-only、spatial_linear_context 1／2)都是真實的線性殘差與其配對的回音估計,輸出守衛不改它們;error_spec 是 [前一 formed hop | 本 hop formed hop] 的 STFT,unity IFFT＋overlap-add 在每個 hop(含守衛觸發的 hop)重建前一個 formed hop。輸出守衛每 hop、每個模式求值一次(本 hop usable 判定確定後、任何 context 提前離開前):output_capture_when_linear_unusable(預設開)、本 hop 線性估計不可用、且 sum|error_spec|² > sum|error_spec+echo_spec|²(嚴格大於、float32 pairwise 歸約,C 與 Python 的歸約相同,相同頻譜得到相同決定;STFT 各自計算,C 對 Python 的契約是:除了雙方都 unusable 且相對能量差 |Σ|E|²−Σ|Y|²|/Σ|E|² 在 1e-6 tie band 內的 hop 以外,每個 hop 的決定一致;band 內的 hop 在對拍的每個 cell 逐一計數並印出,band 外有任何不一致即失敗;固定的近門檻 fixture 要求完全相等)時,渲染底座是擷取訊號 error_spec+echo_spec,否則是 error_spec。底座由 aec_get_output_base()(AecOutputBase{struct_size, n_freqs, guard_active, base_spec})取得;自己合成的消費端渲染 base_spec × 增益,不是 error_spec × 增益,底座不與 formed_hop 配對。相容性注意:仍然渲染 error_spec 的頻域消費端會靜默失去守衛(破壞性行為變更,改渲染 base_spec × 增益);時域 seam 消費端(formed_hop、AecLinearContext.formed_linear_hop)沒有守衛,也沒有時域渲染底座。aec_get_output_base() 先檢查 struct_size(輸入):小於 sizeof(AecOutputBase) 回 −1 且不寫入,較大的值可接受、只寫已知前綴。需與 aec_process() 逐位元相同地合成時,用 aec_synthesis_window() 取函式庫自己的合成窗給 AcStftConfig.window(audiolib 預設 sqrt-Hann 差在最後一個 float 位元)。aec_post_reset_serial() 是硬 post 鏈 reset 的不消耗計數器(aec_reset() 是獨立呼叫、回傳時已 +1;處理呼叫內只有硬 delay 變更使 filter 重啟才會 +1,bad-relock 還原是 soft、不 +1):消費端在 serial 改變的那個 hop(aec_reset() 之後則是之後處理的第一個 hop),於第一次 CNG 抽樣與反轉換／OLA push 之前清自己的 OLA 尾巴並把 CNG 種子設回 AEC_CNG_SEED(42),不得因此 reset AEC;NR／NN 是否跟著 reset 是應用的政策。res_floor_protect(本 hop 是否啟用 double-talk RES floor 保護;Audio_ALG 的 4ch mcab_fuse() 目前不讀本欄位,彙整的是有貢獻 lane 的 max_dt／max_sat／all_converged／usable_linear)與 usable_linear(本 hop 的可用線性估計判定;0 時 r2 是保守的非線性估計——遠端功率乘上預設 echo-path 增益,不是由線性回音估計推導,可能遠高於根本不存在的殘留回音)是這個 seam 額外帶的兩個純量;res_floor_protect 由近端最近有聲音的 latch 觸發。所有指標都 alias AEC 內部 per-hop buffer——下一次任何 process 呼叫前必須讀完。

AecLinearContext seam(aec_get_linear_context(),時域,外接 NN 後級用):formed_linear_hop(post 鏈有跑時為 e_form,即真實的 formed 線性殘差,從不是 capture;否則 raw 線性輸出)、aligned_far_hop(本 hop PBFDKF 實際吃到的時域 far,alias a->far_hop)。delay_state 誠實語意:

  • AEC_LINEAR_DELAY_UNLOCKED — 內容是未補償的 raw far:MATCHED 延遲尚未擷取、或 FIXED ring 未填滿(前 ⌈fixed/hop⌉ 個 hop;再下一次 process 呼叫就能供應該偏移,即回報 LOCKED)。另外超出可擷取上限的 bulk delay 永遠停在 UNLOCKED(估計器不會擷取也不會報錯),fail-open 策略歸整合端。
  • AEC_LINEAR_DELAY_LOCKED — 已用穩定 offset 補償。EXTERNAL_ALIGNED(舊寫法 enable_delay_est=0)從第一個 hop 起即為 LOCKED(delay_samples=0、confidence=1.0、generation 恆定——呼叫端保證輸入 far 已對齊,seam 如實轉述這個契約);FIXED 於 ring 填滿後進入 LOCKED(delay_samples=固定值)。
  • AEC_LINEAR_DELAY_CHANGED — 恰在 offset 於本 hop 移動的那個 hop 回報(下一 hop 回到 LOCKED);下游應 flush far 特徵快取。

generation 在每次 ring 讀取 offset 改變時 +1(首次擷取、確認位移——含不設任何旗標的 soft-recovery realign——以及 aec_reset()),飽和於 0xFFFFFFFF 不回繞。請輪詢 generation 而不是對 delay_samples 做差分(瞬時 A→B→A 位移對差分不可見)。

延遲為脈衝實測(AEC/docs/c_user_manual_zh_TW.md §3「演算法延遲(實測)」),無 look-ahead。可擷取上限是編譯期常數(matched filter 搜尋長度 × 4 倍降取樣),調 max_delay_ms 不會提高;48 kHz 內部先降到 16 kHz 估計再 ×3 回傳。另注意 aec.h 寫的 ~509 ms 是「可靠峰值」定義、608 ms 是幾何全跨度——兩種定義,非矛盾(見 nn_integration_interface.md)。delay estimator(matched filter)本身的機制/語意/語料延遲統計詳見 AEC/docs/delay_estimator_design_zh_TW.md。delay_num_filters config(Python+C,n=1..5,預設 5=行為不變)可依場景縮小 matched filter 算力:可靠搜尋上限 125/221/317/413/509 ms 對應 n=1..5,預設 delay_est_period_s = 0(每 hop 全速分析)時每少一組省 ~4.2 MMAC/s 的搜尋算力,**且固定省 5,728 B/filter(四個格點都一樣)**,見上方「Delay mode」節;僅在系統延遲已由 fixed_delay_samples 補償的部署縮小,bench/dataset 維持 5。

Warm-up:warmup_frames=100(10 ms 基準著作 ≈1000 ms;於 aec_carve() 對實際 hop 重定時,例如 16k/256 內部變 125 hop)期間濾波器以較積極方式收斂。延遲估計需 delay_aec_n_updates() ≥ 3 且 solid 才擷取;delay_est_period_s > 0 時,估計穩定 delay_est_init_s=0.3 秒後 duty-cycle 把 matched-filter 分析降到 1-in-K(ERLE 看門狗回退);預設 0.0 = 每 hop 全速分析。delay_acquire_warm_transfer=1(預設)在首次擷取時平移已學到的 IR 而非歸零,避免開場「垂直線」回音。
