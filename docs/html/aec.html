AEC C library(單聲道)— lib/aec/c_impl

概要

單聲道 PBFDKF 回音消除器的 float32 C 實作(Python aec.py 為演算法規格)。一個 hop 的處理鏈:mic 端 HPF → 飽和偵測 → AEC3 matched-filter 延遲估計 + 參考訊號 ring buffer 對齊 → PBFDAF shadow / PBFDKF main 線性濾波 → AEC3 post(殘留回音抑制 RES + CNG)。全部 state 收在單一 Aec struct(caller pool 或單一 heap arena),process 熱路徑零 malloc(make test-zero-heap 實測 50 個 init/process/reset/destroy 週期 allocator 呼叫為 0)。heap 與 caller-pool 兩條建構路徑輸出逐位元相同(test_static_aec:669,824 樣本 byte-equal)。

沒有任何 NN/NPU 成分:本函式庫是純 DSP,跨 hop 的 state 全部由 C struct 保存,host 不需另存任何 state。AecResContext / AecLinearContext 兩個 seam 是外接 NN 後級(RES/NR)時的接點,見 lib/aec/docs/nn_integration_interface.md。

API 用法

#include "aec.h"

AecConfig cfg;
aec_config_from_preset(&cfg, AEC_PRESET_BALANCED, 16000);
/* 可選:cfg.fft_size = 512;  10ms-authored 常數在建構時(aec_carve)
 * 才對最終 hop 重定時,所以覆寫 fft_size 是安全的 */

/* A. caller pool(嵌入式建議;零 heap) */
size_t bytes = aec_get_mem_size(&cfg);          /* 回 0 = config 無效 */
Aec* a = aec_init(pool, bytes, &cfg);            /* pool 需 16-byte 對齊 */

/* B. heap(單一 malloc arena) */
Aec aec;                                          /* struct 由呼叫端持有 */
if (aec_create(&aec, &cfg) != 0) { /* 失敗 */ }

int hop = aec_hop_size(a);
for (每個 hop) {
    aec_process(a, mic, ref, out);   /* 各恰好 hop 個 float32 樣本 */
}
aec_destroy(a);   /* aec_init 實例為 no-op;pool 由呼叫端釋放 */

Delay mode(cfg.delay_mode,init 時決定、instance 存活期間 immutable,三態互斥,非法組合被 aec_validate_config() 拒絕而非 clamp):

mode合法欄位行為
AEC_DELAY_MATCHED(預設)delay_num_filters = 1–5;fixed_delay_samples 須為 −1AEC3 matched-filter 線上估計延遲,參考環形緩衝套用
AEC_DELAY_FIXEDfixed_delay_samples ≥ 0;delay_num_filters 須維持 5不建 estimator;配置剛好 fixed_delay_samples + hop_size 的環形緩衝套用固定延遲
AEC_DELAY_EXTERNAL_ALIGNEDfixed_delay_samples 須為 −1;delay_num_filters 須維持 5不建 estimator、不建環形緩衝;輸入 ref 視為已對齊

delay_num_filters(僅 MATCHED)主要是**記憶體旋鈕、其次才是算力旋鈕**:每少一個 filter 省 ~4.2 MMAC/s 的「全速搜尋」算力,但出貨的 duty-cycle 讓 bank 只在 8-30% 的 hop 實跑,且每 hop 的 decimator/ring 地板與 n 無關——實測 n=5→1 的攤提成本只差 ~0.3-0.7µs/hop。**且在四個格點上都固定省 5,728 B**(bank/render ring/兩個 histogram 皆依 n 從 pool 切出 —— 這是 pool-first 重構後的行為;RAM 不再是編譯期上限)。aec_get_mem_size(balanced, 16k/256) 實測(KISS):

Backward-jump quarantine(cfg.delay_backward_quarantine_enabled,預設 0=關閉,關閉時輸出逐位元不變;_s 預設 1.0 秒,於 aec_carve() 依 resolved hop 換算成 estimation cycle 數、下限 1):僅作用於 MATCHED 的 Path B(鎖定後的延遲變更)。只隔離「比現行延遲**更早**、且線性 filter 在目前對齊上仍明顯在消除回音」的候選——判別式是新公開的唯讀 aec_linear_is_cancelling(const Aec*)(windowed ERLE > 2.5 dB **或** 近期 inst-ERLE 峰值 > delay_acquire_inst_erle_db;兩個讀數未被填過時為 0 ⇒ fail-open),多實例的呼叫端(4 聲道 wrapper)用同一支函式問同一個問題。往後跳的候選與首次擷取完全不受影響;隔離**有上限**,窗到期即採用,消除能力崩掉則立即放行——所以它**只延後、不治癒** pre-echo 誤鎖。實測(16k/fft 512/hop 256,true 6400 誤鎖 4800):窗 0.5/1.0/2.0/4.0 s = 31/62/125/250 hops,誤鎖採用點由 hop 49 移到 80/111/174/299;multipath 新增路徑四種增益全部重鎖、最壞慢一個窗。

拆解成 estimator/ring 兩個具名子集用 aec_get_mem_breakdown(&cfg, &out)(AecMemBreakdown{total_bytes, estimator_bytes, ring_bytes};total_bytes 就是 aec_get_mem_size() 本身,不是另一套算式)。四格點 × n=1..5 與 FIXED 多個 delay 值的完整實測表見 lib/aec/docs/c_user_manual_zh_TW.md §4/§6.7。

四個 process 進入點推進完全相同的內部 state(都經 aec_process_core()),只差結果怎麼交付,可在同一實例上自由交錯、不需 reset:

進入點用途
aec_process(a, mic, ref, out)lockstep(離線/同執行緒)。與 Python 規格對齊的標準路徑;結果 memcpy 進 out。
aec_process_context(a, mic, ref)context-only:跑完整線性 + AEC3 post,但不寫 out(省一次 O(hop) memcpy)。給只讀 aec_get_res_context() 的呼叫端(mono pipeline 即此模式)。
aec_process_context_shared_far(a, mic, ref, far_spec)多實例共用遠端 FFT:borrow 別的 lane 已算好的 far spectrum(必須是同一 hop、同一 far 訊號的頻譜;ref 仍必填)。傳 NULL 退回自算。儀表:aec_far_fft_real_compute_count()。
aec_analyze_render(a, ref) + aec_process_capture(a, mic, out)串流(render/capture 非同步)。SPSC:恰一個 render 執行緒 + 恰一個 capture 執行緒可無鎖並行。單執行緒 lockstep 呼叫時與 aec_process() 逐位元相同。underrun → 以全零 hop 處理並回 AEC_BUF_RENDER_UNDERRUN;overrun → drop-new / consumer catch-up,回 AEC_BUF_RENDER_OVERRUN。aec_reset()/aec_destroy() 前必須先靜止兩側執行緒。

Preset(唯一差異軸):mild / balanced / aggressive 只差 min_gain_floor_far_active_db = −20 / −28 / −38 dB(SuppressionGain far-active 最低增益地板)。其餘所有欄位相同。

執行期改強度(aec_set_preset()):既然差異只是一個純量 clamp,preset 可以在 running 實例上重新指定,不必重建——濾波器、延遲鎖定、每一條平滑歷史、far-active latch 與 DominantNearend 計數器全部繼續跑。

int aec_set_preset(Aec* a, AecPreset preset, float ramp_ms);

/* 使用者轉動強度旋鈕:在兩個 hop 之間呼叫,100 ms 內以 dB 線性走到新地板 */
if (aec_set_preset(a, AEC_PRESET_AGGRESSIVE, 100.0f) != 0) { /* 引數不合法,實例未變 */ }
aec_process(a, mic, ref, out);

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 preset 從頭建一個新實例」持有的 float 完全相同;> 0 以 dB 線性走過去、每 hop 一步、精確落在目標(非漸近),上限 60 s。mild ↔ aggressive 是 18 dB 落差且地板是硬 clamp、下游無平滑,所以 ramp 有其必要。ramp 途中再呼叫會從當前 live 值重新起走;aec_reset() 保留目標、丟棄 ramp 進度。回 0,或 −1(NULL / 超出 enum 的 preset / 超出範圍的 ramp_ms)且什麼都不寫——與 aec_config_from_preset() 遇到不認得的值退回 balanced 相反,setter 直接拒絕。在兩個 hop 之間呼叫、與 process 序列化;非 thread-safe。

底層 primitive suppression_gain_set_split_floor_far_active_db(SuppressionGain*, float db, float ramp_ms)(suppression_gain.h)是 public 的,因為四麥克風產品共用的 post 級抑制器是一個沒有任何 Aec 擁有的 SuppressionGain。db 以驗證器自己的範圍 [−300, 50] 檢查(執行期不可能裝進 init 當初會拒絕的值);同樣不動平滑歷史/latch/DNE 計數器/initial_state。

兩件量測前必須知道的事。(1)以 spatial_linear_context 建的 lane 從不走到 suppression_gain_get_gain(),對它呼叫本函式依建構方式即為無效操作;四麥克風產品要改的是核心自己那一個共用 post 級抑制器,用 four_aec_nr_res_set_aec_preset()。(2)far-active 地板只在 far-active 且非 double-talk 的 hop 生效——DT 期間套的是 DT 地板(三個 preset 完全相同),latch 觸發前套的是 far-silent 地板;同一個 gain 還決定 comfort noise 量(振幅 ∝ sqrt(1 − G_res²),地板越深 CNG 越多)。所以整段錄音的平均移動幅度會小於 dB 落差,只量 echo/degradation 的 A/B 會把 CNG 變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。Python 對應 AEC.set_preset(preset, ramp_ms=0.0)(不合法引數丟 ValueError)。

AecResContext seam(aec_get_res_context(),頻域,外接 NR/RES 用):error_spec = formed 線性輸出的 50%-overlap periodic-sqrt-Hann STFT E(f)(音訊尺度);echo_spec 為對應回音估計、near_spec = error_spec + echo_spec;res_gain = AEC3 SuppressionGain G_res(f) ∈ [0,1];r2(殘留回音 PSD)與 comfort_noise(CNG N²)為 int16² 尺度(除以 32768² 得 |E|² 音訊功率尺度)。頻域欄位僅在 enable_res=1 或 return_res_context=1 時非 NULL;spatial_linear_context=1 時 res_gain 恆為 NULL(該 lane 的 G_res 根本沒算,NULL 表示「未計算」而非「全抑制」)。context-only(enable_res=0 + return_res_context=1)的 capture 回退:上一 hop usable_linear=0、且選中殘差本 hop 能量大於 mic capture 時,formed 輸出(formed_hop/error_spec/AecLinearContext.formed_linear_hop)改吐 capture 本身——殘差比被減數還大代表濾波器在加訊號,不是在消回音。切換由既有 30-sample 交叉淡化承接,所以是穩態退回而非逐樣本上界。near_spec = error_spec + echo_spec 恆等式仍成立(連續落在 capture 時 echo_spec → 0;單一 hop 因為前半 block 仍是前一 hop 的 e_form 而不會恰為 0)。linear_hop(raw 線性殘差)不受影響,enable_res=1 仍由 post 鏈自己的頻域 guard 負責、輸出逐位元不變。所有指標都 alias AEC 內部 per-hop buffer——下一次任何 process 呼叫前必須讀完。

AecLinearContext seam(aec_get_linear_context(),時域,外接 NN 後級用):formed_linear_hop(post 鏈有跑時為 e_form——context-only 下可能是 capture,見上段;否則 raw 線性輸出)、aligned_far_hop(本 hop PBFDKF 實際吃到的時域 far,alias a->far_hop)。delay_state 誠實語意:

  • AEC_LINEAR_DELAY_UNLOCKED — 內容是未補償的 raw far:MATCHED 延遲尚未擷取、或 FIXED ring 未填滿(前 ⌈fixed/hop⌉ 個 hop;再下一次 process 呼叫就能供應該偏移,即回報 LOCKED)。另外超出可擷取上限的 bulk delay 永遠停在 UNLOCKED(估計器不會擷取也不會報錯),fail-open 策略歸整合端。
  • AEC_LINEAR_DELAY_LOCKED — 已用穩定 offset 補償。EXTERNAL_ALIGNED(舊寫法 enable_delay_est=0)從第一個 hop 起即為 LOCKED(delay_samples=0、confidence=1.0、generation 恆定——呼叫端保證輸入 far 已對齊,seam 如實轉述這個契約);FIXED 於 ring 填滿後進入 LOCKED(delay_samples=固定值)。
  • AEC_LINEAR_DELAY_CHANGED — 恰在 offset 於本 hop 移動的那個 hop 回報(下一 hop 回到 LOCKED);下游應 flush far 特徵快取。

generation 在每次 ring 讀取 offset 改變時 +1(首次擷取、確認位移——含不設任何旗標的 soft-recovery realign——以及 aec_reset()),飽和於 0xFFFFFFFF 不回繞。請輪詢 generation 而不是對 delay_samples 做差分(瞬時 A→B→A 位移對差分不可見)。

逐階段耗時:aec_get_last_timing() 回最近一個 hop 的 delay_us/frontend_us/linear_us/steering_us/res_us(微秒;五者刻意不等於整通呼叫——steering_us 涵蓋主濾波器到 post 之間的 stationarity refresh/ERL 發布/DT analyzer/EPV/misadjustment,補上原本量不到的 ~13% 盲區)。預設關閉——make PROFILE=1(即 -DAEC_STAGE_TIMING=1)才會編進去,否則每個 hop 五欄全讀 0;每 hop 每實例七次 clock 讀取,release build 一次都不做。目標平台沒有 POSIX CLOCK_MONOTONIC 時用 -DAEC_NOW_US=board_timer_us 換掉時鐘(純識別字;替代時鐘必須單調)。詳見 docs/c_user_manual_zh_TW.md §6.6b。

Debug:aec_debug_status()(唯讀、零熱路徑成本)回 delay_samples(−1=未擷取)、delay_confidence(0/0.5/1.0)、delay_updates、erle_windowed_db、usable_linear、filter_converged、near_power/out_power(EMA α=0.95)、duty_hops_total/duty_hops_run(matched-filter duty-cycle 機制的**實測**——非估計——engagement census,自 create/init/reset 起累積;僅 MATCHED 累積,其他 mode 恆 0;純診斷,不影響輸出,byte-exact 證明見 CHANGELOG 產品化 A 線 step 4)。

延遲為脈衝實測(lib/aec/docs/c_user_manual_zh_TW.md §3「演算法延遲(實測)」),無 look-ahead。可擷取上限是編譯期常數(matched filter 搜尋長度 × 4 倍降取樣),調 max_delay_ms 不會提高;48 kHz 內部先降到 16 kHz 估計再 ×3 回傳。另注意 aec.h 寫的 ~509 ms 是「可靠峰值」定義、608 ms 是幾何全跨度——兩種定義,非矛盾(見 nn_integration_interface.md)。delay estimator(matched filter)本身的機制/語意/語料延遲統計詳見 lib/aec/docs/delay_estimator_design_zh_TW.md。delay_num_filters config(Python+C,n=1..5,預設 5=行為不變)可依場景縮小 matched filter 算力:可靠搜尋上限 125/221/317/413/509 ms 對應 n=1..5,每少一組省 ~4.2 MMAC/s 的 full-rate 搜尋(**攤提後受 duty-cycle 稀釋,實測 n=5→1 只差 ~0.3-0.7µs/hop**),**且固定省 5,728 B/filter(四個格點都一樣)** —— pool-first 重構後 RAM 隨 n 縮小,不再是編譯期上限,見上方「Delay mode」節;僅在系統延遲已由 fixed_delay_samples 補償的部署縮小,bench/dataset 維持 5。

Warm-up:warmup_frames=100(10 ms 基準著作 ≈1000 ms;於 aec_carve() 對實際 hop 重定時,例如 16k/256 內部變 125 hop)期間濾波器以較積極方式收斂。延遲估計需 delay_aec3_n_updates() ≥ 3 且 solid 才擷取;估計穩定 delay_est_init_s=0.3 秒後 duty-cycle 把 matched-filter 分析降到 1-in-K(ERLE 看門狗回退)。delay_acquire_warm_transfer=1(預設)在首次擷取時平移已學到的 IR 而非歸零,避免開場「垂直線」回音。
