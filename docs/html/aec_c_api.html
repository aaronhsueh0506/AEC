AEC C API 使用說明 — lib/aec/c_impl

本頁是整合者視角的 API 說明:init/process 要呼叫什麼、input/output 怎麼給、每個參數調了會有什麼結果、跟 NN 後級搭配時要怎麼用。演算法內部機制見 aec.html;完整欄位與錯誤語意的 canonical 出處是 AEC/docs/c_user_manual_zh_TW.md。函式內部自行呼叫的子模組不在本頁範圍。

1. 你只需要一個 header

#include "aec.h"    /* 唯一使用者面 header */

Include path 必須同時有兩個目錄——aec.h 會 include audio_common 的 fft_wrapper.h 與 hpf.h:

-I<AEC>/c_impl/include  -I<audio_common>/include
include/ 底下另有 29 個 header,全部是內部的。aec.h 之所以 include 其中 7 個(外加 audio_common 的 fft_wrapper.h 與 hpf.h),是因為 Aec 與 AecConfig 不是 opaque struct(子模組 by value 內嵌),編譯器需要完整定義——那是編譯依賴,不是 API surface。pbfdkf.h／delay_aec3.h／aec3_post.h／suppression_gain.h 這些不要直接呼叫。
唯一例外:自行在 AEC 之外做 post-beam RES 時(4ch 就是這樣),才會用到 suppression_gain.h 的 primitive。

2. 這個 lib 可以設定的 grid

訊號格點由 (sample_rate, fft_size) 成對決定,必須命中下表其中一列(aec.c:227-233);hop = fft_size/2、n_freqs = fft_size/2+1。

sample_ratefft_size = framehophop 時長n_freqs狀態
160002561288 ms129產品預設(低延遲、低運算)
1600051225616 ms257產品替代
48000102451210.667 ms513產品
800025612816 ms129LEGACY,非產品 grid

兩個產品 sample rate(16k／48k),而 16 kHz 是唯一有兩種 hop 可選的。

fft_size = 0(auto)一律被拒(aec.c:238)。16 kHz 有兩個合法 grid,library 不猜——建立實例前必須 resolve 成明確值。只有 aec_config_defaults()／aec_config_from_preset() 會替你填該 rate 的第一列作為預設。

16k 選 hop 128 還是 256

fft 256 / hop 128fft 512 / hop 256
延遲8 ms/hop,較低16 ms/hop
頻率解析度129 bins257 bins,較高——長混響與 tonal echo 分得更開
每秒運算次數加倍 → CPU 較高減半 → CPU 較低
記憶體(balanced/MATCHED n=5)KISS 385,440 B／NE10 384,832 BKISS 513,968 B／NE10 512,592 B
partition 數filter_length 832 / 128 → 7832 / 256 → 4

所有以「10 ms 為單位」撰寫的時間常數,都會在 aec_carve() 依實際 hop 自動 retime(aec.c:1448-1455),換 grid 不需要手動換算 tuning。

NR 的 grid 表與這裡不完全相同:NR 另外支援 8k/128,而它的 8 kHz 預設是 128 不是 256。串成一條鏈時不要各自呼叫各自的 default,要由上層 resolve 出同一組 (sample_rate, fft_size, hop) 明確傳給兩邊。

3. 建立與生命週期

Static pool(板端路徑)

AecConfig cfg;
aec_config_from_preset(&cfg, AEC_PRESET_BALANCED, 16000);
cfg.fft_size = 256;                       /* 明確指定,不要留 0 */
cfg.delay_mode = AEC_DELAY_MATCHED;       /* 三態之一,見 §4 */

size_t bytes = aec_get_mem_size(&cfg);    /* 0 = cfg 無效 */
void  *pool  = board_alloc_aligned(16, bytes);   /* 基底必須 16-byte 對齊 */
Aec   *aec   = pool ? aec_init(pool, bytes, &cfg) : NULL;
if (!aec) { /* cfg 無效 / 未對齊 / pool 太小 */ }

int hop = aec_hop_size(aec);              /* 128 */
while (streaming) aec_process(aec, mic, ref, out);

aec_destroy(aec);      /* static instance 不會釋放 caller pool */
board_free(pool);

Heap(桌面/測試)

Aec aec;                                  /* caller 擁有這個 struct */
if (aec_create(&aec, &cfg) != 0) { /* cfg 無效或 malloc 失敗 */ }
aec_destroy(&aec);                        /* 會 free 內部 arena */
規則細節
對齊16 bytes。aec_init() 在寫入任何 byte 之前就檢查,未對齊回 NULL 且不動 pool
查 size 與 init 必須用同一份 cfg兩者各自獨立計算,傳不同 cfg 不會被偵測(只有 mem_size < need 這一層防護)。這是契約要求,程式不強制
不要把 byte 數寫死數值隨 backend／config／struct 大小整批移動。永遠用當前 cfg 呼叫 aec_get_mem_size()
init-time immutablesample_rate／fft_size／delay_mode／delay_num_filters／filter_length／n_partitions。改了必須重查 size 並重新 init
拆解查詢aec_get_mem_breakdown(&cfg,&bd) → total_bytes／estimator_bytes／ring_bytes。內部會重跑一次 validate,不要放 hot path

4. Delay mode — 三選一,init-time 決定

這是整合時最先要決定的事,因為它同時改變 pool layout 與 API 可用性。

AEC_DELAY_MATCHED(預設)AEC_DELAY_FIXEDAEC_DELAY_EXTERNAL_ALIGNED
什麼時候用一般產品:延遲未知或會變route delay 已由 bring-up 量得且固定HAL／上游保證 ref 已對齊

5. 每-hop 處理入口 — 選哪一個

所有入口的所有 buffer 一律是 hop_size 個 float;函式沒有長度參數,傳錯長度不會替你報錯。

入口什麼時候用輸出
aec_process(a, mic, ref, out)預設:lockstep,要拿時域輸出out,依 §7 三種模式
aec_process_context(a, mic, ref)接 NN 後級:只讀 context,永不取時域音訊。比上者恰好省一次 O(hop) memcpy—
aec_process_context_shared_far(a, mic, ref, far_spec)多 lane 每 hop 看到完全相同的 far:一條 lane 自算 FFT,其餘借用—
aec_analyze_render(a, ref) + aec_process_capture(a, mic, out)render 與 capture 分執行緒(SPSC)out
Aliasing 很寬鬆:aec_process_core() 在最開頭就把 mic／ref memcpy 進內部 buffer,之後再也不讀;out 直到最後一行才寫。所以 out 可以 alias mic 或 ref,mic 與 ref 也可以互相 alias。
四個入口推進完全相同的 state(都經 aec_process_core),差別只在要不要把結果複製出來 → 可在同一 instance 上任意交錯,不需要中間 reset。單執行緒下先 aec_analyze_render(ref) 再 aec_process_capture(mic,out),輸出與 aec_process(mic,ref,out) 逐位元相同。

Streaming 的回傳值 AecBufferingEvent

值意義
AEC_BUF_NONE正常
AEC_BUF_RENDER_UNDERRUNcapture 跑在前面,FIFO 空 → 該 hop 用靜音 ref 處理
AEC_BUF_RENDER_OVERRUNrender 堆積超過 FIFO:aec_analyze_render 丟新的;aec_process_capture 跳過陳舊 backlog
AEC_BUF_API_SKEW保留,目前不會被回傳——library 內沒有任何寫入點

Threading:SPSC only。恰一條 thread 呼 aec_analyze_render、恰一條呼 aec_process_capture,不需外部鎖。不涵蓋:第二條 producer/consumer、與 render/capture 併發呼叫 aec_reset()/aec_destroy()、把 offline aec_process() 與 streaming pair 混用。

6. 搭配 NN model:不需要 DSP 後級時怎麼用

線性 AEC 常常只當前級,殘留回音抑制交給 NN(Align-ULCNet 等)。此時不要照預設整條跑完再丟掉後半段——那是白算的。正確做法:

AecConfig cfg;
aec_config_from_preset(&cfg, AEC_PRESET_BALANCED, 16000);
cfg.fft_size           = 256;
cfg.enable_res         = 0;   /* 不跑 DSP 殘留抑制器,NN 取代它 */
cfg.return_res_context = 1;   /* 但 post block 仍跑,把頻域 seam 填好 */

/* ... init 同 §3 ... */

AecResContext    ctx;
AecLinearContext lin;

aec_process_context(aec, mic, ref);     /* 不要 aec_process:沒有時域輸出要拿 */
aec_get_res_context(aec, &ctx);         /* 頻域 seam */
aec_get_linear_context(aec, &lin);      /* 時域 seam:線性殘差 + 已對齊 far */
/* → 把 ctx/lin 餵給 NN,在下一次 process 之前用完 */
要關的為什麼
enable_res = 0NN 取代 SuppressionGain。輸出保持線性殘差,不套 DSP 抑制
enable_cng 自動失效CNG 是在 aec3_post_apply_output() 內注入的,enable_res=0 時該函式根本不會被呼叫 → 不必特別關,它已經是 inert
return_res_context = 1關鍵。若也設 0,post block 整段不跑,error_spec／res_gain／r2／comfort_noise／formed_hop 全部是 NULL
spatial_linear_context = 1只有多 lane fused post-stage 才用(4ch)。本 lane 的 G_res 完全不算(res_gain 回 NULL),但 DominantNearend hold-state 仍每 hop 更新。強制要求 enable_res==0 && return_res_context==1
borrowed pointer 的效期只到下一次 process。AecResContext／AecLinearContext 的每個指標都 alias 內部 per-hop buffer,四個 process 入口任一個都會覆寫它們。要跨 hop 保存必須自己複製走。
接 NR 時 r2 要先換尺度:AecResContext.r2 與 comfort_noise 是 int16² scale,要除以 32768² 才是 audio power。res_gain 則是 amplitude [0,1]。
用 generation 做快取失效:AecLinearContext.generation 每次 ring offset 改變就 +1(飽和不 wrap)。只比較 delay_samples 會漏掉 A→B→A 的暫態。

完整的 NN seam 規格(三個 swap point、wiring contract)見 AEC/docs/nn_integration_interface.md。

7. 三種輸出模式

enable_resreturn_res_contextpost blockout 內容context 頻域欄位

01跑(context_only)線性殘差全部有效
00不跑線性殘差大部分是 NULL;只剩診斷用的 echo_spec／near_spec

AEC 不做最終 peak limiter。產品需要 limiter／AGC／DRC 時放在整條 chain 的最後。

9. 執行期控制

函式語意回傳
aec_set_preset(a, preset, ramp_ms)只改 min_gain_floor_far_active_db 這一個純量。濾波器／delay state／所有平滑歷史／far-active latch／DominantNearend 計數器全部不動。ramp_ms==0 → 下一 hop 生效,落點與「一開始就用該 preset 建構」逐位元相同;>0 → 在 dB 上線性走,且精確落到 target(不是漸近逼近)0／-1。-1 時一個 byte 都沒寫
aec_apply_external_realign(a, delta)僅 EXTERNAL_ALIGNED。delta = 新對齊 − 舊對齊。條件符合時平移已學到的 IR,否則做 filter-only reset(保留 synthesis OLA,輸出連續無垂直線)1=warm transfer／0=filter reset 或 delta==0／-1=NULL 或 mode 不對
aec_reset(a)回到「全新 instance」狀態。會重啟 WOLA → spectrogram 上會有垂直線。若只是外部對齊改變,請用上一個函式而不是這個void,⚠ 無 NULL 檢查
aec_set_preset() 對非法 preset 是拒絕(回 −1),與 aec_config_from_preset() 靜默退回 balanced 的行為相反。ramp_ms 範圍 [0, 60000],ramp_ms==0 不是錯誤。ramp 進行中再呼叫 → 從當前 live 值重新起走。
全部必須在 hop 之間呼叫、與 process() 序列化;非 thread-safe。aec_reset() 另外要求 render/capture thread 已靜止。
若 lane 是用 spatial_linear_context=1 建立的(4ch),aec_set_preset() 依構造為 inert——該 lane 根本不跑 suppressor 的 gain path。4ch 要改強度請用 four_aec_nr_res_set_aec_preset(),它針對的是共用的 post 級抑制器。

建議 poll 頻率:每秒一次。這是 pull 型結構化快照,在 release build 一樣可用(NO_STDIO=1 的 archive 仍匯出 aec_debug_status)——詳見 串接範例 的 DEBUG 章節。

AecStageTiming(需 build flag)

五個 uint32_t 微秒欄位:delay_us／frontend_us／linear_us／res_us／steering_us。

五者相加不等於整個呼叫——res_us 收尾後還有 per-sample power EMA 與收斂偵測。做 breakdown 的 caller 必須明確帶出這個 remainder,否則百分比會說謊。delay_us 已從 frontend_us 減回去,兩者不重複計。解析度 μs,小於 1 μs 的 stage 讀 0。
必須建 library 本身(PROFILE=1);只在 consumer 端開 flag 只會拿到一堆 0——而且函式不會告訴你它沒被啟用。

缺 POSIX CLOCK_MONOTONIC 的板子:加 -DAEC_NOW_US=<fn>,fn 必須是無參數、回傳 uint32_t 微秒的純識別字,且必須單調。

-ffp-contract=off 是強制的,在所有 caller 旗標之後才 append,無法被覆蓋。Makefile 在 parse 時就拒絕 EXTRA_CFLAGS 內出現 -Ofast／-ffast-math／-ffp-contract=,也拒絕覆寫 CFLAGS 等變數;唯二 hook 是 EXTRA_CFLAGS／EXTRA_LDFLAGS。

12. 整合檢查清單

  • (sample_rate, fft_size) 命中 §2 表其中一列,且與鏈上其他 lib 同一組。
  • fft_size 明確指定,沒有留 0。
  • delay_mode 明確選定;fixed_delay_samples 依 mode 是 -1 或 >=0。
  • 查 pool size 與 aec_init() 用同一份 cfg;基底 16-byte 對齊。
  • 每次 process 恰好傳一個 hop;ref 是實際送往喇叭的 render reference,且與 mic 同 sample clock。
  • borrowed context pointer 沒有跨下一次 process 保存。
  • 接 NR 時 r2／comfort_noise 已除以 32768²。
  • 接 NN 時 enable_res=0 且 return_res_context=1(只設前者會拿到一堆 NULL)。
  • stream boundary 有 aec_reset();外部對齊改變則改用 aec_apply_external_realign()。
  • application 與 archive 使用相同 BACKEND／SIMD／FP 旗標。
  • 最終 float→PCM 前做 saturating conversion;limiter 只放在整條 chain 最後。
