AEC C library 細節 — 記憶體拆解、執行期強度、耗時與 debug

概要

本頁收 aec 中會把單頁撐過 30 KB 的細節:記憶體拆解、aec_set_level() 的 ramp 語意與量測注意事項、live observer、逐階段耗時與 debug 狀態。呼叫順序、delay mode 表、process 進入點、seam 契約、block diagram、泳道圖、I/O 表、State 表、延遲與檔案清單仍留在原頁。

記憶體拆解

拆解成 estimator/ring 兩個具名子集用 aec_get_mem_breakdown(&cfg, &out)(AecMemBreakdown{total_bytes, estimator_bytes, ring_bytes};total_bytes 就是 aec_get_mem_size() 本身,不是另一套算式)。四格點 × n=1..5 與 FIXED 多個 delay 值的完整實測表見 AEC/docs/c_user_manual_zh_TW_01_lifecycle.md §4/AEC/docs/c_user_manual_zh_TW_02_config.md §6.7。

執行期改強度(aec_set_level)的細節

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 level 從頭建一個新實例」持有的 float 完全相同;> 0 以 dB 線性走過去、每 hop 一步、精確落在目標(非漸近),上限 60 s。mild ↔ aggressive 是 18 dB 落差且地板是硬 clamp、下游無平滑,所以 ramp 有其必要。ramp 途中再呼叫會從當前 live 值重新起走;aec_reset() 保留目標、丟棄 ramp 進度。回 0,或 −1(NULL / 超出 enum 的 level / 超出範圍的 ramp_ms)且什麼都不寫——與 aec_config_from_level() 遇到不認得的值退回 balanced 相反,setter 直接拒絕。在兩個 hop 之間呼叫、與 process 序列化;非 thread-safe。

底層 primitive suppression_gain_set_split_floor_far_active_db(SuppressionGain*, float db, float ramp_ms)(suppression_gain.h)是 public 的,因為四麥克風產品共用的 post 級抑制器是一個沒有任何 Aec 擁有的 SuppressionGain。db 以驗證器自己的範圍 [−300, 50] 檢查(執行期不可能裝進 init 當初會拒絕的值);同樣不動平滑歷史/latch/DNE 計數器/initial_state。

兩件量測前必須知道的事。(1)以 spatial_linear_context 建的 lane 從不走到 suppression_gain_get_gain(),對它呼叫本函式依建構方式即為無效操作;四麥克風產品要改的是那一個共用 post 級抑制器(AecRes;由 4ch 應用在 mcab flow 之後自己建立,mcab 不含 RES),用 aec_res_set_level()。(2)far-active 地板只在 far-active 且非 double-talk 的 hop 生效——DT 期間套的是 DT 地板(mild/balanced 共用 −20 dB,aggressive 是 −30 dB,刻意跟另外兩個不同,否則三個 level 在 DT 觸發時會蓋回同一個值),latch 觸發前套的是 far-silent 地板;同一個 gain 還決定 comfort noise 量(振幅 ∝ sqrt(1 − G_res²),地板越深 CNG 越多)。所以整段錄音的平均移動幅度會小於 dB 落差,只量 echo/degradation 的 A/B 會把 CNG 變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。Python 對應 AEC.set_preset(preset, ramp_ms=0.0)(不合法引數丟 ValueError)。

Live observer(預設關閉)

Live observer(cfg.live_observer_enabled,預設 0=關閉,關閉時輸出逐位元不變):第三個獨立 PBFDAF 實例(跟 shadow_filter 同一個 struct,固定 NLMS、lightweight=1 省近端的加窗/未加窗兩個 FFT,同 shadow 省法),讀取遠端 ring 比主濾波器的延遲補償讀取早 live_observer_shift_ms(預設 24.0 ms)。每 hop 把自己的誤差能量 EMA 跟主濾波器(R² 實際採用的那條選線 sel_esw,不是恆取 main)的誤差能量 EMA 比較(EMA 時間常數 live_observer_corrob_ms 預設 100.0 ms、容忍度 live_observer_corrob_margin_db 預設 0.0 dB),只有在觀察器沒有比主濾波器差時才信任其證據;證據本身夾在主濾波器殘留回音功率以內(min()),經 max(r2, evidence) 注入 residual-echo R²(只到 live_observer_max_hz 預設 1000.0 Hz 的低頻段),從不碰輸出、delay 或任一濾波器的視窗/taps。注入邏輯跑在 aec_post_run_observer_step()(src/aec_post.c)內,不在 aec_process_core() 主迴圈(跟 shadow 不同),因為要讀當下 hop 才算出的 dominant_ne/usable_linear 判定。記憶體增量(aec_get_mem_size() 實測,delay_num_filters=5):8k/256 +29,472 B、16k/256(預設)+38,768 B、16k/512 +58,656 B、48k/1024 +141,648 B。算量增量用 bench_rtf --live-observer 在目標格點量測;未進任何預設組合。

逐階段耗時與 debug

逐階段耗時:aec_get_last_timing() 回最近一個 hop 的 delay_us/frontend_us/linear_us/steering_us/res_us(微秒;五者刻意不等於整通呼叫——steering_us 涵蓋主濾波器到 post 之間的 stationarity refresh/ERL 發布/DT analyzer/EPV/misadjustment)。預設關閉——make PROFILE=1(即 -DAEC_STAGE_TIMING=1)才會編進去,否則每個 hop 五欄全讀 0;每 hop 每實例七次 clock 讀取,release build 一次都不做。目標平台沒有 POSIX CLOCK_MONOTONIC 時用 -DAEC_NOW_US=board_timer_us 換掉時鐘(純識別字;替代時鐘必須單調)。詳見 docs/c_user_manual_zh_TW_02_config.md §6.6b。

Debug:aec_debug_status()(唯讀、零熱路徑成本)回 delay_samples(−1=未擷取)、delay_confidence(0/0.5/1.0)、delay_updates、erle_windowed_db、usable_linear、filter_converged、near_power/out_power(EMA α=0.95)、duty_hops_total/duty_hops_run(matched-filter duty-cycle 機制的**實測**——非估計——engagement census,自 create/init/reset 起累積;僅 MATCHED 累積,其他 mode 恆 0;純診斷,不影響輸出)。
