AEC C API 使用說明 — AEC/c_impl

呼叫順序與可編譯範例見 aec_usage、時序圖見 aec_sequence、外部／內部參數見 aec_params／aec_params_internal。本頁是整合者視角的 API 說明:init/process 要呼叫什麼、input/output 怎麼給、每個參數調了會有什麼結果、跟 NN 後級搭配時要怎麼用。演算法內部機制見 aec.html;完整欄位與錯誤語意的 canonical 出處是 AEC/docs/c_user_manual_zh_TW.md 索引所指的分冊(欄位參考 ../../reference/configuration.md §6、錯誤語意表 ../../reference/lifecycle.md §5)。函式內部自行呼叫的子模組不在本頁範圍。

1. 你只需要一個 header

#include "aec.h"    /* 唯一使用者面 header */

Include path 必須同時有兩個目錄——aec.h 會 include audiolib 的 fft_wrapper.h(Complex 型別在那裡):

-I<AEC>/c_impl/include  -I<audiolib>/common/include
include/ 只有一個 header:aec.h(對外 API)。其餘全部在 include/internal/(不屬於公開介面,只用公開 API 的整合者不需要把它加進 include 路徑):aec_internal.h(pipeline 用的庫內部介面)、aec_balanced_config.h(產生的表)等。Aec 是不透明型別(aec.h 只有 typedef struct Aec Aec;):用 aec_create() 取得指標,或用 aec_init() 放進自己的 pool;不能以值持有、取 sizeof 或讀欄位。pbfdkf.h／delay_aec.h／aec_post.h／suppression_gain.h 等內部實作標頭也在 include/internal/。
殘留回音抑制增益階段不是獨立的公開介面(見 RES 增益階段與舒適噪音);舒適噪音填補 aec_apply_cng_spec() 宣告在 aec.h(底層 aec_cng_fill() 在內部標頭 aec_internal.h)。Aec 本身也有四麥克風的陣列實例(n_mics = 4,融合與一次 G_res 都在實例內),見 §5a。

2. 這個 lib 可以設定的 grid

訊號格點由 (sample_rate, fft_size) 成對決定,必須命中下表其中一列(aec_tuning.c 的 AEC_GRID_TABLE);hop = fft_size/2、n_freqs = fft_size/2+1。

兩個產品 sample rate(16k／48k),而 16 kHz 是唯一有兩種 hop 可選的。

fft_size = 0(auto)一律被拒。16 kHz 有兩個合法 grid,library 不猜——建立實例前必須 resolve 成明確值。只有 aec_config_from_level() 會替你填該 rate 的第一列作為預設。

所有以「10 ms 為單位」撰寫的時間常數,都會在 aec_carve() 依實際 hop 自動 retime,換 grid 不需要手動換算 tuning。

NR 的 grid 表與這裡不完全相同:NR 另外支援 8k/128,而它的 8 kHz 預設是 128 不是 256。串成一條鏈時不要各自呼叫各自的 default,要由上層 resolve 出同一組 (sample_rate, fft_size, hop) 明確傳給兩邊。

3. 建立與生命週期

建立、reset 與釋放的最小範例見呼叫使用。固定記憶池在最後一次處理之前均由 caller 持有。Aec* aec_create(const AecConfig*) 做一次 16-byte 對齊的配置(aec_get_mem_size() 位元組),aec_destroy() 釋放那一塊——之後指標失效,呼叫端不再 free;aec_init() 的 pool 實例由呼叫端自己回收 pool。aec_synthesis_window() 回傳的合成窗在實例自己的 pool 裡,借用它的 AcIstft 不得比 Aec 活得久。

回傳碼(AecStatus)

碼值意義
AEC_OK0成功
AEC_ERR_ARG-1NULL、太短的 struct_size、範圍外引數,或(陣列)輸入含非有限值;實例不動
AEC_ERR_MODE-2呼叫需要比 AecConfig.residual 更深的模式(例如 OFF 時的 aec_process_residual()),或對陣列實例呼叫 aec_process()

被拒絕的呼叫不寫任何輸出,唯一例外是 AEC_ERR_DSP。aec_get_mem_requirements、aec_set_level、aec_synthesis_window 沿用「0 成功、-1 失敗」;aec_apply_external_realign() 回結果(1／0／-1);aec_is_valid_sample_rate() 是述詞(1／0)。

5. 每-hop 處理入口 — 選哪一個

所有入口的所有 buffer 一律是 hop_size 個 float;函式沒有長度參數,傳錯長度不會替你報錯。

入口什麼時候用輸出
aec_process(a, mic, ref, out)預設:lockstep,要拿時域輸出out,依 §7 四種模式
aec_process_linear(a, mic, ref) + aec_process_residual(a, NULL)接 NN 後級／自己套增益:兩段式,結果從 aec_get_residual()／aec_get_linear() 讀,永不取時域音訊。比上者恰好省一次 O(hop) memcpy 與函式庫的合成;residual == OFF 時只需第一個呼叫—
aec_process_linear_shared_far_from(a, mic, ref, far_owner)(內部標頭 aec_internal.h)多 lane 每 hop 看到完全相同的 far:一條 lane 自算 FFT,其餘借用它同 hop 的遠端頻譜及其 magnitude²(Aec owner),之後同樣接 aec_process_residual()—
陣列實例(n_mics = 4):aec_process_linear(a, mics, ref) → aec_get_array() → 呼叫端 beamformer → aec_process_residual(a, &beam)四麥克風:mics 是交錯的 float[hop][4],ref 是 float[hop];beam.weights 為聲道優先 Complex[4][n_freqs]。aec_process() 在陣列上回 AEC_ERR_MODE—(從 aec_get_residual()／aec_apply_gain()／aec_apply_cng() 讀;見 §5a)
Aliasing 很寬鬆:aec_stage_linear() 在最開頭就把 mic／ref memcpy 進內部 buffer,之後再也不讀;out 直到最後一行才寫。所以 out 可以 alias mic 或 ref,mic 與 ref 也可以互相 alias。
三個處理入口推進完全相同的濾波器與偵測器 state(都經 aec_stage_linear／aec_stage_residual),差別只在要不要套增益、合成並把結果複製出來 → 可在同一 instance 上逐 hop 交錯,不需要中間 reset(函式庫自己的 OLA 尾巴與舒適噪音產生器只在 aec_process／aec_apply_cng 推進,所以交錯後 aec_process 的 out 不等於一路 aec_process 的 out)。

一次 aec_init()／aec_create() 建出整條四麥克風線性流程:四條 lane(各是一個 EXTERNAL_ALIGNED 的單聲道 Aec)、一個共用 delay 估計器與一份對齊後 far、融合緩衝,全在同一塊記憶池。Beamformer(SRP-PHAT、BF、VAD)與合成不在函式庫內。每個 hop 的序列與可編譯範例見 aec_usage 範例 E、時序見 aec_sequence §6a。

6. 搭配 NN model:不需要 DSP 後級時怎麼用

線性 AEC 常常只當前級,殘留回音抑制交給 NN(Align-ULCNet 等)。此時不要照預設整條跑完再丟掉後半段——那是白算的。正確做法:

AecConfig cfg;
aec_config_from_level(&cfg, AEC_LEVEL_BALANCED, 16000);
cfg.fft_size           = 256;
cfg.residual           = AEC_RESIDUAL_FULL;   /* post block 全跑、把頻域 seam 填好;拆開的進入點不套用任何增益(NN 取代它)。可再降成 ESTIMATE／STATE 省掉用不到的 G_res */

/* ... init 同 §3 ... */

AecResidualView rv = { .struct_size = sizeof rv };
AecLinearView   lin = { .struct_size = sizeof lin };

aec_process_linear(aec, mic, ref);      /* 不要 aec_process:沒有時域輸出要拿 */
aec_process_residual(aec, NULL);
aec_get_residual(aec, &rv);             /* 頻域 seam */
aec_get_linear(aec, &lin);              /* 時域 seam:線性殘差 + 已對齊 far */
/* → 把 rv/lin 餵給 NN,在下一次 process 之前用完 */
要關的為什麼
aec_process_linear() + aec_process_residual()(residual = FULL)NN 取代 SuppressionGain 的輸出:函式庫不套 DSP 抑制、不合成,輸出保持線性殘差(raw_output)。這是舊版「抑制旗標關、context 旗標開」組態的對應寫法
residual = ESTIMATE(或 STATE)選用的進一步省算:不算 G_res(res_gain 回 NULL),r2／comfort_noise 照算;STATE 連這兩者也不算。DominantNearend hold-state 仍每 hop 更新。這兩種模式下 aec_process() 的輸出是線性殘差
enable_cng 不影響拆開的進入點不合成,舒適噪音由呼叫端決定要不要加;自己合成時用 aec_apply_cng()(residual = FULL)或自持產生器狀態的 aec_apply_cng_spec(),種子 AEC_CNG_SEED
residual = OFF 不要用關鍵。OFF 時沒有後級:aec_process_residual()／aec_get_residual() 回 AEC_ERR_MODE,error_spec／res_gain／r2／comfort_noise／formed_hop 都拿不到
borrowed pointer 的效期只到下一次 process。AecResidualView／AecLinearView 的每個指標都 alias 內部 per-hop buffer,任一個 process 入口都會覆寫它們。要跨 hop 保存必須自己複製走。
接 NR 時 r2 要先換尺度:AecResidualView.r2 與 comfort_noise 是 int16² scale,要除以 32768² 才是 audio power。res_gain 則是 amplitude [0,1]。
用 generation 做快取失效:AecLinearView.generation 每次 ring offset 改變就 +1(飽和不 wrap)。只比較 delay_samples 會漏掉 A→B→A 的暫態。

完整的 NN seam 規格(三個 swap point、wiring contract)見 AEC/docs/nn_integration_interface.md。

7. 四種後級模式(AecConfig.residual)

residual進入點post blockout 內容view 頻域欄位
FULL(預設)aec_process跑並套用RES 抑制後 + CNG全部有效
FULLsplit(aec_process_linear + aec_process_residual)跑,不套用—(無 out;結果從 aec_get_residual() 讀,用 aec_apply_gain()／aec_apply_cng() 渲染)全部有效

AEC 不做最終 peak limiter。產品需要 limiter／AGC／DRC 時放在整條 chain 的最後。

9. 執行期控制

函式語意回傳
aec_set_level(a, level)改該 level 的 far-active 最低增益(固定 100 ms 內以 dB 線性走到 target)與 double-talk 最低增益(mild／balanced 相同、aggressive 較深;無 ramp,立即套用)與 split floor 開關(AEC_LEVEL_NO_FLOOR 關閉;布林,同樣立即套用),並把新 level 記成實例的 level。濾波器／delay state／所有平滑歷史／far-active latch／DominantNearend 計數器全部不動。far-active 地板在 dB 上線性走,且精確落到 target(不是漸近逼近),落點與「一開始就用該 level 建構」逐位元相同,DT 地板這段時間早已落地0／-1。-1 時一個 byte 都沒寫
aec_apply_external_realign(a, delta)僅單聲道的 EXTERNAL_ALIGNED(陣列實例回 -1)。delta = 新對齊 − 舊對齊。條件符合時平移已學到的 IR,否則做 filter-only reset(保留 synthesis OLA,輸出連續無垂直線)1=warm transfer／0=filter reset 或 delta==0／-1=NULL 或 mode 不對
aec_reset(a)回到「全新 instance」狀態。會重啟 WOLA → spectrogram 上會有垂直線,並讓 aec_post_reset_serial() +1(aec_reset 是獨立呼叫,不在處理呼叫之內,回傳時 serial 已 +1)。若只是外部對齊改變,請用上一個函式而不是這個void;NULL 與已銷毀的 handle 為 no-op
aec_set_level() 對非法 level 是拒絕(回 −1),與 aec_config_from_level() 靜默退回 balanced 的行為相反。ramp 時間固定 100 ms(內部常數)。ramp 進行中再呼叫 → 從當前 live 值重新起走。
全部必須在 hop 之間呼叫、與 process() 序列化;非 thread-safe。
若 lane 的 residual 低於 FULL(STATE 或 ESTIMATE,4ch),aec_set_level() 依構造為 inert——該 lane 根本不跑 suppressor 的 gain path。陣列實例請對實例本身(它內含融合後共用的 post 級抑制器,見 RES 增益階段)呼叫 aec_set_level()。

AecStageTiming(需 build flag)

五個 uint32_t 微秒欄位:delay_us／frontend_us／linear_us／res_us／steering_us。

五者相加不等於整個呼叫——res_us 收尾後還有 per-sample power EMA 與收斂偵測。做 breakdown 的 caller 必須明確帶出這個 remainder,否則百分比會說謊。delay_us 已從 frontend_us 減回去,兩者不重複計。解析度 μs,小於 1 μs 的 stage 讀 0。
必須建 library 本身(PROFILE=1);只在 consumer 端開 flag 只會拿到一堆 0——而且函式不會告訴你它沒被啟用。

缺 POSIX CLOCK_MONOTONIC 的板子:加 -DAEC_NOW_US=<fn>,fn 必須是無參數、回傳 uint32_t 微秒的純識別字,且必須單調。

12. 整合檢查清單

  • (sample_rate, fft_size) 命中 §2 表其中一列,且與鏈上其他 lib 同一組。
  • fft_size 明確指定,沒有留 0。
  • delay_mode 明確選定;fixed_delay_samples 依 mode 是 -1 或 >=0。
  • 查 pool size 與 aec_init() 用同一份 cfg;基底 16-byte 對齊。
  • 每次 process 恰好傳一個 hop;ref 是實際送往喇叭的 render reference,且與 mic 同 sample clock。
  • borrowed context pointer 沒有跨下一次 process 保存。
  • 接 NR 時 r2／comfort_noise 已除以 32768²。
  • 接 NN 時 residual 設 ESTIMATE／FULL 並用 aec_process_linear() + aec_process_residual()(OFF 會拿不到 view)。
  • stream boundary 有 aec_reset();外部對齊改變則改用 aec_apply_external_realign()(陣列實例不適用)。
  • 陣列實例:mics 交錯成 float[hop][4];每 hop 依序 aec_process_linear() → aec_get_array() → 自己的 beamformer → aec_process_residual();權重有限且不全為零;FULL 不重複呼叫 aec_process_residual();AEC_ERR_DSP 後實例已被重設(serial 前進),下一個成功的 hop 在 OLA push 之前依 serial 清自己的 OLA;serial 只比較「不同」。
  • application 與 archive 使用相同 BACKEND／SIMD／FP 旗標。
  • 最終 float→PCM 前做 saturating conversion;limiter 只放在整條 chain 最後。
