AEC 外部參數與公開函式 — aec.h

概要

外部＝呼叫端能設定的 AecConfig 12 個欄位，加上 aec.h 的公開函式；內部＝庫內部的 AecTuning，由 aec_resolve() 依 (sample_rate, fft_size, n_mics, level) 推導，呼叫端不能設定（見 內部參數）。建議用法：aec_config_from_level() 取得完整設定，只覆寫下表欄位。出處只標檔名與符號名，不標行號。預設值是用本機建置的 aec_config_from_level(&cfg, AEC_LEVEL_BALANCED, rate) 在 8000／16000／48000 逐欄印出核對的（三個取樣率只有 fft_size 不同：256／256／1024）；各旋鈕對音訊的效果見參數效果。

除 level（可用 aec_set_level() 在執行期改）之外，下表所有欄位都是「建立時決定」。改了必須 aec_destroy 後重建，或重新 aec_get_mem_size() + aec_init()。aec_create()／aec_init() 複製設定，事後改手上那份無效；Aec 是不透明型別，沒有可改的內部設定。

1. 公開欄位（AecConfig，sizeof = 48 B）

欄位型別／範圍／單位預設作用與設定時機
sample_rateint；8000／16000／48000（其他一律拒絕，含 44100）呼叫端指定取樣率；mic 與 ref 同率同時鐘。
fft_sizeint；與 sample_rate 成對：16k→256／512，48k→1024，8k→256（legacy）；0 被拒絕8k→256、16k→256、48k→1024（aec_config_from_level 填入，＝aec_default_fft_size）決定 hop = fft_size/2。16k/512 的 hop 是 256（16 ms），延遲加倍、呼叫頻率減半。濾波器長度由取樣率決定（8k：416、16k：832、48k：3072 sample），不是欄位。
n_mics1 或 AEC_ARRAY_MICS（4）14 建出四麥克風陣列實例（見 §3a）；4 只在沒有 AEC_NO_ARRAY 的建置可用。
levelAecLevel：MILD(0)／BALANCED(1)／AGGRESSIVE(2)／NO_FLOOR(3)；範圍外被拒絕BALANCED「回音壓多乾淨 vs 近端保留多完整」的單一取捨軸，也是唯一的強度設定。建立時，或執行期 aec_set_level(a, level)。下方表列它帶出的三個內部值。
residualAecResidualMode：OFF(0)／STATE(1)／ESTIMATE(2)／FULL(3)；範圍外被拒絕FULL後級（殘留回音抑制）做到哪裡。OFF→輸出是線性殘差、演算法延遲 0、回音殘留明顯變多；FULL→完整抑制，固定多 1 hop 延遲（16k/256 = 8 ms），aec_process() 套用增益、加舒適噪音並合成。STATE／ESTIMATE 給自己套增益的整合者（§3）。不影響單聲道實例的 pool 大小（陣列實例則隨它改變，且不接受 OFF）。
delay_modeAecDelayMode：MATCHED(0)／FIXED(1)／EXTERNAL_ALIGNED(2)MATCHED對齊方式的唯一真值；同時決定 pool 佈局。非法組合在建立時被拒絕。陣列實例上描述共用的對齊。
fixed_delay_samplesint，native-rate 樣本；FIXED：0 – 120 x sample_rate；其他模式必須是 -1-1FIXED 的量測系統延遲，同時決定參考環大小（fixed + hop）。
delay_num_filtersint 1–5；僅 MATCHED 合法（其他模式須維持 5）5matched filter bank 大小：主要是記憶體旋鈕（每少一組省 estimator 5,120 B，單通道 MATCHED 合計 11,264 B（48 kHz 23,552 B））；可靠搜尋上限 125／221／317／413／509 ms（n = 1..5）。
enable_cng0／11時域輸出內的舒適噪音注入，只在 residual = FULL 且用 aec_process() 時有作用（拆開的進入點由呼叫端決定要不要呼叫 aec_apply_cng()）；下游已有 CNG 時請關。rv.comfort_noise（PSD）不受它影響。
capture_proxy_channel0–3（單聲道必須 0）0陣列：共用 delay 估計器的 capture 輸入取哪一路麥克風。
delay_backward_quarantine_enabled0／1（單聲道必須 0）0陣列、只在 MATCHED 有意義：比目前 delay 更早的新估計，在 capture-proxy lane 仍在消除期間先保留 _s 秒再採用；消除失效就立刻採用。前向移動與首次取得不受影響。
delay_backward_quarantine_s0–3600 s1.0保留時間，建立時換算成 hop 數（下限 1）。

Level 帶出的三個內部值（由 aec_level_floor_db()、aec_level_dt_floor_db()、aec_level_split_floor_enabled()〔aec_internal.h〕逐 level 印出核對；AecConfig 的其餘欄位四個 level 完全相同）：

Levelfar-active 最低增益（dB）double-talk 最低增益（dB）split floor適用
MILD-20.0-20.01近端音質優先、耦合弱
BALANCED（預設）-28.0-20.01一般通話
AGGRESSIVE-38.0-30.01回音優先、耦合強；double-talk 近端較易被壓
NO_FLOOR-28.0（惰性）-20.0（惰性）0地板全關，軸上最深點，近端損失最大

aec_set_level() 的 far-active 地板固定 100 ms 以 dB 線性走到目標（內部常數，不可調）；double-talk 地板與 split-floor 旗標一律立即階躍。dB 值不對外開放：要提供中間強度請新增 level，而不是讓呼叫端填數字。aec_config_from_level() 對超出 enum 的值不報錯，存成 balanced；直接把 cfg.level 填成範圍外的數字，或 aec_set_level() 收到範圍外的值，則被拒絕（建立回 NULL／size 0，aec_set_level 回 -1）——對外層請先自己檢查 enum 範圍。CLI 的 --level 只收 0–3 的整串數字，其他值以結束碼 2 拒絕。

2. 已不是公開欄位的舊旋鈕

下列原本在 AecConfig 的欄位已移到內部 AecTuning（src/aec_tuning.h），呼叫端不能設定；epc_mu_floor 已刪除。要改變行為時改 level、delay_mode 或 residual。數值、範圍與作用見內部參數與 §8。

舊欄位現況
filter_length、n_partitions由取樣率與 hop 推導（8k：416、16k：832、48k：3072 sample）
enable_highpass、highpass_cutoff_hzmic 路徑高通固定開啟、80 Hz；沒有開關（§8.2）
enable_shadow固定開啟；關閉省 27,888 B（16k/256），只有 AEC_TESTING 的測試鉤子能關
delay_est_period_s、delay_est_init_s、max_delay_ms、delay_buffer_ms（已刪除）內部值；單聲道 MATCHED 的參考環由 estimator 可回報的最大延遲決定，陣列的共用環取內部 max_delay_ms（1024 ms）
min_gain_floor_far_active_db、min_gain_floor_dt_db、min_gain_split_floor_enabled由 level 查表帶出
mu、delta、warmup_frames、偵測器門檻、live_observer_* 等內部調校值（聯合調過）；預設值整理於內部參數

3. 整合者專用（拓樸，不是調參）

欄位範圍預設說明
residual（STATE／ESTIMATE）AEC_RESIDUAL_STATE(1)／AEC_RESIDUAL_ESTIMATE(2)FULL多 lane 呼叫端自己算增益時用：ESTIMATE 不算本 lane 的 res_gain（讀為 NULL）；STATE 只留線性半邊（res_gain／r2／comfort_noise 皆 NULL、res_floor_protect = 0）。搭配 aec_process_linear() + aec_process_residual() 與 aec_get_residual()。對這種單聲道 lane 呼叫 aec_set_level() 回 0 但依構造無效。

3a. 陣列實例（n_mics = 4）的規則

一次 aec_init()／aec_create() 建出四條 lane、共用 delay 估計器與對齊後 far、融合緩衝；beamformer 與合成由呼叫端提供。呼叫序列見 aec_usage 範例 E。

項目規則
residual必須是 STATE／ESTIMATE／FULL（OFF 被拒絕），並改變 pool 大小（16k/256：595,744／691,280／701,280 B，主機實測）
格點只有 16k/256、16k/512、48k/1024；8 kHz 被拒絕
delay_mode／delay_num_filters／fixed_delay_samples描述共用的對齊；每條 lane 以 EXTERNAL_ALIGNED 吃對齊後 far；共用環的容量由內部 1024 ms 的可達延遲決定，duty-cycle 保持時間固定 0.3 s
capture_proxy_channel0–3；共用 delay 估計器只吃這一路，該路失效則陣列鎖不到 delay
delay_backward_quarantine_*見 §1；單聲道必須維持 0、_s 在 [0, 3600]
level／aec_set_level()只作用於融合後的增益階段（FULL）；STATE／ESTIMATE 呼叫回 0 但依構造無效，只更新記錄的 level

6. 驗證規則（被拒絕的設定）

驗證在 aec_create／aec_get_mem_size／aec_get_mem_breakdown／aec_get_mem_requirements／aec_init 內都會先跑；任一欄位不合法整組拒絕（create → NULL、get_mem_size → 0、init → NULL、breakdown／requirements 回負值並清零）。外部拿不到失敗原因；下表是公開欄位的規則。

類別規則
格點(sample_rate, fft_size) 必須是 8k/256、16k/256、16k/512、48k/1024 之一；fft_size = 0 拒絕；歸零的結構（sample_rate = 0）也被拒絕
列舉level 在 0–3、residual 在 OFF(0)…FULL(3)、delay_mode 在 0–2
布林enable_cng、delay_backward_quarantine_enabled 必須是 0 或 1
延遲模式MATCHED：fixed = -1；FIXED：fixed >= 0 且 <= 120 x sr、delay_num_filters = 5；EXTERNAL_ALIGNED：fixed = -1、delay_num_filters = 5；delay_num_filters 1–5
陣列實例n_mics 必須是 1 或 4；n_mics = 4 時 residual 不可是 OFF、格點只有 16k/256／16k/512／48k/1024、capture_proxy_channel 在 0–3；n_mics = 1 時 capture_proxy_channel 與 delay_backward_quarantine_enabled 必須是 0；delay_backward_quarantine_s 在 0–3600；AEC_NO_ARRAY 建置拒絕任何 n_mics != 1
validator 不做的事：範圍只防「崩壞」不防「音質崩壞」，所以內部調校值不開放給呼叫端；公開欄位的組合（例如 fixed_delay_samples 與 delay_mode）在建立時才被檢查，不會被靜默修正。

7. 擁有權、對齊與呼叫契約

  • 輸入 float32、標稱 [-1, 1]；每次呼叫恰好 aec_hop_size() 個樣本，無長度參數。不做 clock drift 補償、不處理負延遲、不做 peak limiting（out 可能略超出 [-1, 1]）。
  • 單一實例非 thread-safe；不同實例彼此獨立。AecResidualView／AecLinearView 的指標在下一次 process／reset 後失效，不可修改、不可 free。
  • NULL 與已銷毀 handle 的行為（本機逐項呼叫核對）：aec_create（cfg 為 NULL）、aec_init／aec_init_ex 回 NULL；aec_get_mem_size 回 0；aec_destroy／aec_reset 為 no-op；aec_hop_size、aec_far_fft_real_compute_count、aec_linear_is_cancelling、aec_post_reset_serial 回 0；aec_set_level、aec_apply_external_realign 回 -1；aec_process／aec_process_linear／aec_process_residual／aec_apply_gain／aec_apply_cng／aec_get_residual／aec_get_linear／aec_get_array／aec_get_mem_breakdown 回 AEC_ERR_ARG（-1），檢視結構除 struct_size 外清零；aec_debug_status、aec_get_last_timing 把 *out 清零（out 為 NULL 則直接返回）。
  • pool 大小（本機 NE10 後端、balanced、MATCHED n = 5、aec_get_mem_size）：8k/256 211,552 B；16k/256 239,920 B；16k/512 352,288 B；48k/1024 776,224 B。調整量（16k/256）：delay_num_filters 5→1 -45,056 B；EXTERNAL_ALIGNED -62,352 B；FIXED 1600 -55,440 B；內部的 shadow filter 開關（只有測試鉤子能關）-27,888 B；內部的 live observer（預設關，只有測試鉤子能開）+38,768 B；單聲道的 residual／enable_cng 不影響（陣列實例的 pool 隨 residual 改變，見 §3a）。絕對值隨函式庫內部結構整批移動，一律以 aec_get_mem_size() 為準。
  • 建置：同時連結 libaudio_common.a（含一個 C++ 翻譯單元，用 C++ driver 連結）與 -lm；-ffp-contract=off 必須；SIMD=0 與 SIMD=1 的輸出不保證逐位元相同，同一組旗標下 heap 與 pool 才保證相同（test_static_aec）。

調整參數的音訊效果

8.1 抑制強度 — mild/balanced 只差一個值，aggressive 差兩個，NO_FLOOR 關閉地板

Levelfar-active 最低增益double-talk 最低增益效果
AEC_LEVEL_MILD−20.0−20.0遠端單講時 echo 壓得最淺，近端被誤削的風險最低
AEC_LEVEL_BALANCED−28.0（預設）−20.0（預設）—
AEC_LEVEL_AGGRESSIVE−38.0−30.0echo 壓最深，近端被誤削風險最高；DT 地板也跟著深化，否則 double-talk 觸發時 mild／balanced／aggressive 會蓋回同一個 −20.0，聽不出差異
AEC_LEVEL_NO_FLOOR−28.0（惰性）−20.0（惰性）同時把 split floor 設為 0，地板全關，軸上最深點、近端損失最大；兩個 dB 值只是佔位（重複 balanced），不起作用

執行期用 aec_set_level() 改（AEC API §9）。aec_level_floor_db() 等查表函式在內部標頭 aec_internal.h，不是公開介面。

量測前務必知道：far-active 地板只在 far-active 且非 double-talk 的 hop 咬得到。DT 期間走的是 double-talk 地板（mild/balanced 共用 −20 dB，aggressive 是 −30 dB）；far-active latch 觸發前用的是 far-silent 地板。而且同一個 gain 也決定 comfort noise 的量 → 只量 echo／degradation 的 A/B 會把 CNG 的變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較，並實際試聽。

8.2 前端 HPF（內部，固定）

項目值說明
mic 路徑高通固定開啟、截止 80 Hz只作用於 mic 路徑；切掉 mic 的 DC／rumble。沒有開關也沒有截止頻率欄位（原 enable_highpass／highpass_cutoff_hz 已是內部值）。需要更高的截止（例如風噪重的場合）時，在餵進 AEC 之前用 audiolib 的 hpf.h 自己再做一級。
far（ref）路徑沒有 HPF，連實例都不存在——整個 lib 只有一個 hp_mic。這是刻意的設定。若 ref 需要 HPF，請在餵進 AEC 之前用 audiolib 的 hpf.h 自己做，但先確認你真的需要。

8.3 輸入電平 / gain

AEC 的 AecConfig 沒有任何 gain 欄位。輸入電平調整屬於 AEC 之前的前級，由整合端負責：

Audio_ALG 沒有現成的 gain 模組：整合端自行在餵進 AEC 之前乘上固定增益，需要時自己加 clip。

電平會直接改變 AEC 行為：內部的削波門檻（0.95）判定 clipping，內部的參考訊號 soft-clip 會對參考訊號貼近實際被 clip 的喇叭輸出。把輸入 gain 調到讓 ref 常態接近滿刻度，會讓線性模型失準、ERLE 下降。詳見 audiolib API。

下表只說明各內部值的作用，讓你看得懂行為從哪裡來；它們是聯合調過的，單獨改任何一個都沒有保證（測試經 aec_testing_* 鉤子覆寫）。完整清單與家族分類見內部參數。
