AEC 內部參數 — 可以調,但不建議開放

概要

本頁列出不屬於 外部參數 的內部調校值(原本是 AecConfig 的欄位,現在是庫內部 AecTuning 的欄位,呼叫端不能設定;epc_mu_floor 已刪除),以及編譯期固定的常數。這些值不開放給第三方(測試經 aec_testing_* 鉤子覆寫):共同原因是它們是聯合調出來的(預設值是整體調過的,見手冊 §6.6),單獨改任何一個都沒有保證;validator 的範圍只防崩壞,不防音質崩壞。出處見 include/internal/aec_tuning.h(宣告與預設在 aec_tuning.c)。下表值只有測試能覆寫。

1. 內部調校值(AecTuning,原 AecConfig 內部欄位)

家族欄位(預設)為什麼不開放
10 ms 格點撰寫、建立時 retime 的時間欄位(6)warmup_frames(100)、epc_hangover(20)、ne_recent_hold(150)、filter_misadjustment_stable_frames(30)、filter_misadjustment_hangover_frames(100)、shadow_err_alpha(0.80)填的值是「N x 10 ms 的實際時長」,由 aec_carve 換成當前格點的 hop 數(例:16k/256 下 warmup_frames = 100 變 125 hop),不是直接的 hop 計數;外部極易誤解單位而靜默出錯。shadow_err_alpha 同樣依格點重算(16k/256 為 0.8365)。
適應步進(4)mu(0.3)、delta(1e-8)、shadow_mu_min(0.5)、shadow_mu_nlms(0.5)直接決定收斂／發散邊界;validator 範圍極寬(mu 到 10),範圍內大部分值會發散或不收斂。
偵測門檻(7)epc_total_rise(1.5)、epc_delta_threshold(0.3)、ne_recent_threshold(0.3)、ne_recent_sustain(3)、saturation_threshold(0.95)、filter_misadjustment_scale_min(0.5)、filter_misadjustment_scale_max(2.0)與其他偵測器聯合調過;scale_min > scale_max 會被 validator 接受(無跨欄位檢查);ne_recent_sustain 刻意不 retime(每 hop 遞增的計數,實際時長隨格點變:16k/256 約 24 ms、16k/512 約 48 ms、48k 約 32 ms),因為三個格點各自的行為已個別驗證。
延遲取得策略(4)delay_acquire_protect_converged(1)、delay_acquire_warm_transfer(1)、delay_acquire_inst_erle_db(4.0)、delay_est_init_s(0.3)影響冷啟動前一秒有沒有回音。MATCHED 環(單聲道與陣列)固定為 estimator 可回報延遲上限 + hop,可擷取上限由 delay_num_filters 決定;max_delay_ms、delay_buffer_ms 已刪除。
Double-talk 政策(2)dt_aware_recovery_soft(1)、dt_aware_res_floor_enabled(1)與 level 的 DT 地板綁在一起,關掉會讓 level 的 DT 差異失效。
保護性開關(應維持預設)(2)enable_saturation(1)、saturation_softclip_ref(1)關掉沒有合理使用情境(削波偵測與參考訊號軟限幅)。
預設關閉、未過 default-on 門檻的實驗(7)live_observer_enabled(0)、live_observer_shift_ms(24)、live_observer_max_hz(1000)、live_observer_mu(0.3)、live_observer_corrob_ms(100)、live_observer_corrob_margin_db(0)、cng_n2_windowed_psd(0)不要在產品路徑開啟。observer 開啟的記憶體增量(aec_get_mem_size 實測):8k/256 +29,472 B、16k/256 +38,768 B、16k/512 +58,656 B、48k/1024 +141,648 B;算量增量以 bench_rtf --live-observer 在目標格點量測:待量測。
衍生值(2)filter_length(8k:416、16k:832、48k:3072 sample)、n_partitions(0 = 自動)由取樣率與 hop 推導;手填只會製造不一致。
前端與結構(4)enable_highpass(1)、highpass_cutoff_hz(80)、enable_shadow(1)、delay_est_period_s(0:每 hop 全速分析)mic 高通與 shadow filter 固定開啟;delay_est_period_s 非 0 可能改變選到哪個 lag(不只是變慢),未過驗收。
由 level 帶出(3)min_gain_floor_far_active_db、min_gain_floor_dt_db、min_gain_split_floor_enabled唯一入口是 AecConfig.level 與 aec_set_level(),值見外部參數的 level 表。

加總 6+4+7+4+2+2+7+2+4+3 = 41,等於 include/internal/aec_tuning.h 的 AecTuning 欄位數(kalman_q_high、kalman_q_low 已刪除,epc_mu_floor 已刪除);公開的 AecConfig 另有 12 個欄位,見外部參數。

3. 內部函式與 header(整合者不得依賴)

範圍內容為什麼不開放
include/internal/aec_tuning.h、include/internal/aec_config_build.haec_resolve、aec_resolve_tuned、aec_tuning_valid、aec_apply_level、aec_build_sg_config、aec_synth_window_build、aec_sg_tables_decode庫內部共用的設定建構器(定義在 aec_tuning.c 與 aec_config_build.c,由 aec.c、aec_array.c 與 aec_res.c 使用;後者為內部模組,標頭 include/internal/aec_res_internal.h);回傳的 tuning 表指向靜態 per-rate 資料。
include/internal/aec_scale.haec_blocks_to_hops、aec_ms_to_hops、aec_growth_rehop、AEC_PSD_SCALE…參考常數(int16^2 PSD、4 ms 區塊)換算到本庫尺度的 init-only helper。
子模組 header(全在 include/internal/,不在 include/ 根目錄)pbfdkf.h、delay_aec.h、aec_post.h、aec_state.h、suppression_gain.h、residual_echo_estimator.h、epc_shadow.h、detectors.h… 及其 *_get_mem_size／*_init_static 函式隨版本改變;應用程式只用頂層 aec_get_mem_size／aec_init(STATIC_MEMORY.md)。
suppression_gain_set_split_floor_*_far_active_db、_dt_db、_enabled是 aec_set_level 的底層 primitive;整合端改用它。
struct Aec 欄位include/internal/aec_impl.haec.h 只宣告 typedef struct Aec Aec;,結構內容由編譯器擋在庫外(只有 aec.c、aec_array.c 與白箱測試看得到)。

4. 建置期旗標(內部)

SIMD(0 → -DSIMD_KERNELS_FORCE_SCALAR)、NO_STDIO、PROFILE(預設 1;-DAEC_STAGE_TIMING=$(PROFILE),0 關閉逐階段耗時)、WERROR、EXTRA_CFLAGS、AEC_TESTING(絕不可出貨)、AEC_NO_ARRAY(單聲道函式庫,不編陣列實例);-ffp-contract=off -fno-math-errno 由 Makefile 強制,不是選項。說明見 AEC API §11 與 AEC/c_impl/README.md。
