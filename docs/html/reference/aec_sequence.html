AEC 流程時序圖 — AEC/c_impl

概要

本頁用 <pre> ASCII 時序圖畫 AEC 庫的呼叫順序。lifeline:Application(呼叫端)、Aec(aec.c)、audiolib(FFT／HPF 等共用庫)、下游 stage(NR／合成,屬 Audio_ALG 與 audiolib,非 AEC 庫)。AEC 庫是純 DSP:沒有 NN runtime／加速器 lifeline,跨 hop 的 state 全在 Aec 內,呼叫端不需另存。箭頭上的名稱都是真實函式;aec_* 的 static 函式為 aec.c 內部步驟(列出是為了對照順序,不是 API)。用法與範例見 aec_usage。

順序取自 aec.c 的 aec_stage_linear 與 aec_stage_residual(shadow 先於 main;aec_process_linear 做到 aec_update_windowed_erle 為止,aec_process_residual 接著做 post 區塊)。residual = OFF 時整個 post 區塊跳過,final_out 為線性殘差;只有 residual = FULL 的 aec_process 套用增益並合成。

 |                                                |                                       |                             |

 |- E, R2, CN, g_res -------------------------------------------------------------------->|                             |

 |< g_nr ---------------------------------------------------------------------------------|                             |
 | g = min(g_nr, g_res);P = rv.base_spec * g(不是 error_spec;即 aec_apply_gain(aec, g_nr, P));aec_apply_cng(aec, g_nr, P)(或自持狀態的 aec_apply_cng_spec(&rng, P, cn, g_res, g_nr, n))
 |- ac_istft_push(P) -------------------------------------------------------------------------------------------------->|
 |< out[hop] -----------------------------------------------------------------------------------------------------------|

單聲道實際串接見 Audio_ALG pipelines/mono/aec_nr_res/main.c。AEC 端用預設的 residual = FULL 並以 aec_process_linear + aec_process_residual 驅動。aec_process、aec_process_linear + aec_process_residual 推進相同的內部 state,可在同一實例上交錯。單聲道的 RES 增益(res_gain)由 post 區塊在 AEC 的呼叫內算出,不另建獨立的增益階段;純 AEC 的範例可以直接呼叫 aec_process(),RES 與最後的合成都在同一個呼叫內完成。

4. 被拒絕／錯誤路徑

 Application                                                  Aec
 |                                                            |
 |- aec_get_mem_size(&bad_cfg) ------------------------------>|
 |< 0 --------------------------------------------------------| 不是負值;務必檢查 == 0
 |- aec_init(unaligned_or_small_pool, ...) ------------------>|
 |< NULL -----------------------------------------------------| 未 16-byte 對齊 / mem_size < need / cfg 無效:寫入 pool 之前就拒絕
 |- aec_create(&bad_cfg) ----------------------------------->|
 |< NULL ------------------------------------------------------| cfg 無效或 malloc 失敗
 |- aec_process(...) ---------------------------------------->|
 |< AecStatus --------------------------------------------| 設定錯誤在建立階段擋下;呼叫錯誤回 AEC_ERR_ARG／AEC_ERR_MODE／AEC_ERR_SEQUENCE,實例原封不動、不寫 out;
 |                                                         | 結果溢位的 hop 回 AEC_ERR_DSP:實例已像 aec_reset() 重設,out 寫成零
 |- aec_set_level(aec, bad_level) ------------------------->|
 |< -1 -------------------------------------------------------| NULL / enum 外;什麼都沒寫
 |- aec_set_level(residual 低於 FULL 的 lane, ...) --------->|
 |< 0 --------------------------------------------------------| 回 0 但依構造無效:該 lane 不走抑制增益路徑
 |- aec_apply_external_realign(aec, d) ---------------------->|
 |< -1 -------------------------------------------------------| NULL、delay_mode != EXTERNAL_ALIGNED 或陣列實例(合法的單聲道實例上 d == 0 回 0)
 |- aec_get_residual(aec, NULL) ----------------------------->|
 |< AEC_ERR_ARG ------------------------------------------------| NULL 輸出或 struct_size 太小:你的結構不被寫入
 |- aec_reset(NULL) ----------------------------------------->|
 |                                                            | NULL 為 no-op;aec_process(NULL, ...) 回 AEC_ERR_ARG
aec_set_level 對 residual 低於 FULL(STATE／ESTIMATE)的 lane 結果依構造無效,但不是回 -1(本機實測回 0):它只更新該 lane 記錄的 level 與其 SuppressionGain 目標,而該 lane 從不計算增益。需要改強度時,對陣列實例呼叫 aec_set_level()(它重設融合後共用的增益階段)。

6a. 麥克風陣列實例(n_mics = 4)的一個 hop

 Application                              Aec 陣列實例 (aec_array.c)                          呼叫端 beamformer
 |                                         |                                                  |
 |- aec_process_linear(a, mics, ref) ----->|                                                  | mics = 交錯 float[hop][4]
 |                                         | 非有限輸入 -> AEC_ERR_ARG(什麼都不改,上一個 hop 的檢視仍可讀)
 |                                         | 共用 delay 估計器(capture_proxy_channel)-> 接納規則 -> 對齊後 far
 |                                         |   delay 改變(changed)-> 對四條 lane 做 realign
 |                                         | lane 0 算遠端 FFT;lane 1..3 借用;每條 lane:線性 stage + lane 後級
 |< AEC_OK ---------------------------------| 任一條 lane 的結果不是有限值 -> AEC_ERR_DSP,整個實例已像 aec_reset() 重設
 |- aec_get_array(a, &av) --------------->|                                                  |
 |< lane_error_spec[4] / lane_base_spec[4] / aligned_ref / delay -|                              |
 |- av ----------------------------------------------------------------------------------------->| 權重 W[4][n_freqs]、波束頻譜 E
 |< W, E ---------------------------------------------------------------------------------------|
 |- aec_process_residual(a, &beam) ----->|                                                  | STATE:AEC_ERR_MODE(沒有融合)
 |                                         | 權重須有限且不全為零,否則 AEC_ERR_ARG(hop 保持開啟)
 |                                         | 融合:near、r2(相干)、comfort noise(功率和)、渲染底座 base
 |                                         | FULL:對融合頻譜算一次 G_res;同 hop 第二次呼叫 -> AEC_ERR_SEQUENCE
 |< AEC_OK ---------------------------------| ESTIMATE:無 G_res,同 hop 可重複融合
 |- aec_get_residual(a, &rv) ------------>|                                                  | formed_hop = NULL、echo_spec = NULL
 |- aec_post_reset_serial(a) ------------->|                                                  | 四條 lane 計數之和;與自己存的不同 -> 先清自己的 OLA
 |- aec_apply_gain(a, g_nr, spec) -------->|                                                  | spec = base * min(G_res, g_nr)(FULL)
 |- aec_apply_cng(a, g_nr, spec) --------->|                                                  | 實例內產生器,serial 變動時由實例自己重設為 AEC_CNG_SEED
 |- 反轉換 + overlap-add(呼叫端)

被拒絕的呼叫:陣列實例的 aec_process() 與 aec_process_linear_shared_far_from() 回 AEC_ERR_MODE,aec_apply_external_realign() 回 -1。第一次取得的共用 delay 立即採用;之後的移動必須超過 32 個 sample,且在候選值存活的 3 個 hop 內以差距小於 16 個 sample 再被提出一次才接納。範例見 aec_usage 範例 E,契約見 AEC/docs/reference/integration.md §8.8。目前遠端側狀態仍是每條 lane 各一份。

6. 4 聲道:陣列實例

 Application                                                    Aec 陣列實例 (n_mics = 4)
 |                                                            |
 |- aec_process_linear(a, mics, ref) ------------------------>|  共用 delay、對齊後 far、4 條 lane 的線性級
 |- aec_get_array(a, &av) ---------------------------------->|  lane 誤差頻譜 -> SRP-PHAT、beamformer 權重 W、波束成形後頻譜 E
 |- aec_process_residual(a, &{W, E}) ------------------------>|  融合 E, Y, R2, N2;內部 RES 階段算一次 g_res
 |< AEC_OK / AEC_ERR_* ------------------------------------------|  AEC_ERR_DSP: 實例已自行重設
 |- aec_get_residual(a, &rv) ------------------->|  rv.base_spec = 渲染底座 B(各 lane 渲染底座的加權和;沒有 lane 守衛觸發時就是 E)
 | g = min(g_nr, g_res)
 |- aec_apply_gain(a, g_nr, P);aec_apply_cng(a, g_nr, P) --->|  P = B * g,再加舒適噪音(實例內產生器)
 | rv.post_reset_serial 與自己存的不同 -> ac_istft_reset,在 aec_apply_cng 與 ac_istft_push 之前(不可呼叫 aec_reset)
 |- aec_set_level(a, level) ------------------------------->|  hop 之間
 |- aec_reset(a) ------------------------------------------->|  串流邊界;保留地板目標

波束成形(SRP-PHAT、BF、VAD)在函式庫之外,由呼叫端在 aec_process_linear() 與 aec_process_residual() 之間算;合成(反轉換與 overlap-add)同樣在函式庫外。residual = STATE 的陣列只跑 lane(無融合、無增益階段,aec_process_residual() 回 AEC_ERR_MODE)。契約見 AEC/docs/reference/integration.md §8.8,RES 階段內部見 aec_res。

7. 泳道圖:啟動期與延遲(橫軸 hop)

以 16 kHz／256(hop 128 = 8 ms)為例;其他格點把 hop 換成 256／512 即可。

hop →               1        2      ...     13       14       15     ...
------------------------------------------------------------------------------------
caller         mic,ref -> aec_process / aec_process_linear + aec_process_residual -> out(residual = FULL 時晚 1 hop)
------------------------------------------------------------------------------------
EXTERNAL       LOCKED(delay_samples = 0,confidence 1.0,從第 1 個 hop 起)
FIXED d=1600   UNLOCKED  UNLOCKED  ...  UNLOCKED  LOCKED   LOCKED   ...
               (前 ceil(d / hop) = 13 個 hop:ref ring 尚未填到 d + hop 個樣本,
                aligned_far_hop 是未補償的 raw far)
MATCHED        UNLOCKED(delay_samples = -1) ......... 擷取後該 hop 回報 CHANGED 一次,再 LOCKED
               擷取條件:n_updates >= 3 且延遲在 ring 容量內(aec.c aec_align_reference)
------------------------------------------------------------------------------------
線性濾波器     warmup_frames(authored 100 x 10 ms;16k/256 內部重定時為 125 hop,約 1 s)內較積極收斂
RES / post     residual = FULL:輸出比線性路徑晚 1 hop(WOLA);residual = OFF:0 延遲
seam 讀者      ctx / lin 有效到「下一次任何 process 或 reset 呼叫」
格點hopresidual = FULL 演算法延遲(脈衝實測,手冊 §3)MATCHED 搜尋範圍的幾何全 span
8 kHz／256(legacy)12816.000 ms1216 ms
16 kHz／2561288.000 ms608 ms
16 kHz／51225616.000 ms608 ms
48 kHz／102451210.667 ms608 ms

FIXED 的 13 個 UNLOCKED hop 與第 14 個 hop 起 LOCKED,是在暫存複本實跑 aec_get_linear 的結果(16k/256、fixed_delay_samples = 1600)。MATCHED 的實際擷取所需 hop 數隨訊號而定:待量測。可靠搜尋範圍 509 ms(delay_num_filters = 5;單聲道參考環就是依它配置:8,148 + hop sample)與 608 ms 幾何全 span 是兩種定義,見 AEC API §4 與 AEC/docs/delay_estimator_design_zh_TW.md。
