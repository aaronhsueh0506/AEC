1. 什麼是回音消除

在全雙工通話（手機免持、智慧音箱、視訊會議）中，喇叭播放的遠端語音會被麥克風同時收到，造成對方聽到自己說話的回聲。AEC 的任務是從麥克風訊號中移除這個回音，只留下近端用戶的聲音。

圖 1：回音消除場景 — AEC 用已知的 ref 訊號估計並扣除回音
核心原理：喇叭播放的訊號（ref）是已知的。AEC 建立「回音路徑模型」，預測麥克風會收到多少回音，再扣掉，剩下的就是用戶語音。

3. 線性 AEC — Kalman 自適應濾波器

線性 AEC 持續學習「ref → mic 的回音路徑」，用學到的模型預測回音並扣除，剩下 error 就是理想的近端語音。

傳統 NLMS（舊方法）

  • 固定步長更新，收斂慢
  • 環境變化時反應遲鈍
  • DT 期間容易誤學語音

PBFDKF（我們的做法）

  • Kalman 自動調整步長（依信心水準 P/R）
  • 收斂速度快 2–3×
  • 分區頻域處理，可處理長回音路徑
  • DT 期間自動降低步長保護語音
關鍵優勢：Kalman filter 的增益 K 會依目前估計的「系統信心」自動縮放。系統穩定時步長小（不過擬合），路徑突變時步長大（快速追蹤）。這讓 AEC 在移動裝置和快速環境變化下表現遠優於 NLMS。

4. Shadow Filter — 雙濾波器策略

單一濾波器面臨兩難：學太快容易學到 DT 語音，學太慢在 echo path 變化後恢復太慢。雙濾波器策略解決此問題。

圖 3：Shadow filter 策略 — 激進探索 + 保守輸出，最優結果供主濾波器使用
實際效果：喇叭移動或設備轉向時（echo path 突然改變），Shadow filter 約 100–200ms 內先完成重新收斂，Main filter 複製後立即恢復。無此機制則需要 1–3 秒。

5. 雙方通話（Double-Talk）保護

當用戶和遠端同時說話時（Double-Talk），若 filter 照常更新，會把近端語音誤學為回音，導致語音被壓掉。AEC 有多層保護機制。

🎯 DT 偵測

監測 mic/ref 能量比、ERLE 變化，以及 Shadow vs Main 誤差差異。偵測到 DT 時將 filter 學習速率降至 0。

⚡ 能量信號旁路

當 mic 能量遠超 ref 預期（mic > ERL × ref），直接判斷有近端語音，繞過 ERLE 的高耦合盲點。

🛡 RES 放寬門檻

RES 的 per-bin 增益在 DT 期間放寬壓制門檻，確保殘餘估計不過度壓制近端語音。

穩態遠端（白噪音、風扇）場景：自動偵測後切換更保守策略，避免固定頻率訊號把弱語音誤判吸收。

6. 殘餘回音抑制（RES）— 三模組詳解

線性 AEC 的理論上限約 20–30 dB（受 speaker 非線性、空間 reverb tail、模型誤差限制）。RES 是第二層頻域後濾波器，每幀重新決定每個 frequency bin 要乘多少 gain。三個關鍵模組依序串接：

圖 4：RES 內部三階段 — 估計殘餘 → 計算壓制比例 → 設下限避免 musical noise

6.1 Residual Echo PSD — 「殘餘有多少？」

物理意義：每個頻率 bin 估計「線性 AEC 之後還剩多少回音功率」。沒有這個估計，後面所有 gain 決定都是亂猜。輸出單位是頻譜功率（|X|²），與 nearend PSD 對等。

怎麼算

  • 主來源（filter-based）：echo_spec ÷ ERLE — 用 filter 內部已估計的回音頻譜除以當前 ERLE 折扣，推估線性 AEC 漏掉多少。Filter 收斂越好越精準。
  • 備用（render-based）：|ref|² × ERL_avg — 直接拿 ref 能量乘學到的 ERL，filter 不可信時用（冷啟動 / EPC 後 / 低 ERLE confidence）。
  • Reverb tail：把過去 30–60 ms 的殘餘以 IIR 衰減累積（S_tail = α·S_tail + β·S_now），補捉混響尾。
類比：氣象局先預報「明天每小時降雨幾毫米」。要決定「帶不帶傘、撐多大傘」之前，必須先有這個量化估計。RES 後面兩個模組都靠 PSD 的數字做決定。

常見失敗：PSD 過度信任 filter 的早期不準預測 → 壓制過頭傷語音；或 reverb tail 太長 → echo 結束後仍持續壓抑。v3.8 把 ERLE confidence 引進權重，初期 fallback 到 render-based 以避這個雷。

6.2 ENR Gain Gate — 「該壓多重？」

物理意義：ENR = residual_echo_psd ÷ nearend_psd。比例高 (echo dominant) → 該頻率以回音為主 → gain 壓低；比例低 (near-end dominant) → 近端在說話 → gain 接近 1 (不動)。把每個頻率 bin 的 ENR 餵進 sigmoid 平滑函數，得到 0–1 之間的壓制比例。

圖 5：ENR sigmoid gain — 紫線為一般情況；綠色虛線為 DT 偵測時的放寬版（閾值往右抬），確保不誤壓近端語音

關鍵參數

  • threshold：sigmoid 中心 (echo / near-end 平衡點)。預設 ~0 dB。
  • softness：sigmoid 寬度。太硬 → musical noise；太軟 → 漏 echo。
  • DT relax：DTD 觸發時 threshold +4 ~ +8 dB（綠色虛線）→ 同 ENR 下 gain 更高，不誤壓近端。
  • preset 影響：aggressive / maximum 把 threshold 拉低 → sigmoid 整條左移 → 同 ENR 壓得更狠。
類比：自動音量旋鈕。對方在響時轉小，自己人在說話時手放開。Sigmoid 是「平滑過渡」，避免「啪一聲開關」造成的 click/musical noise。

6.3 Spectral Floor — 「不能壓到死」

物理意義：給每個頻率 bin 設定最小 gain 下限 g_min(k)。完全壓到 0 會聽到「musical noise」（被壓制 bin 的殘餘變成隨機尖峰，像鳥叫 / 水滴聲），人耳極為敏感。留下底噪反而聽起來自然。

圖 6：Spectral floor 機制 — 紫虛=ENR 算出的 raw gain；紅虛=舊版固定 −20 dB 下限；綠=v2.7 動態 floor 跟隨 noise；藍=兩者取大值=最終 gain

v2.7 之前 vs 之後

版本下限策略結果
v2.7 之前固定 g_min = 0.1 (−20 dB)低噪場景過度壓 → 死寂；高噪場景殘餘變鳥叫
v2.7 之後min-statistics 動態追蹤過去 1.5 秒 noise floor安靜頻率 floor 低 → 大幅壓制；噪聲頻率 floor 高 → 留住自然底噪

CNG（Comfort Noise Generation，可選）

當 gain 真的觸到 floor 之下，CNG 把該頻率用 形狀化的舒適噪聲（比對 mic 自身的 noise spectrum 形狀產生）填回。聽感上避免 dead-air（電話一片死寂像斷線），但不會增加 echo（因為形狀只取自近端統計，與 ref 無關）。

類比：夜間靜音模式不要把人耳完全塞起來。留一個微弱自然背景音，對方聽起來「還連著」而不是「電話斷了」。

6.4 兩種估計來源（PSD 子層級）

直接估計（filter 收斂後）

用 filter 輸出的 echo_spec 算殘餘 PSD，精度高，可精準壓制而不傷語音。

✓ 啟用條件：ERLE > 10 dB 持續 20 幀

Render-based（收斂前 / EPC 後）

用 ref 訊號 × 學習到的 ERL 保守估計，不依賴 filter 品質。

✓ 啟用條件：filter 未收斂、ERLE 低、或 EPC 觸發後

7. 主要改進歷程

從 v2.0 到 v3.8.3，累計超過 120+ 小時研發，透過 AEC Challenge 800 cases 評測驅動每次迭代。每次改動都要通過 800-case AECMOS 評測才收版。

版本說明：
  • v3.8.1 = Python 演算法定版（音質行為固定在這版）
  • v3.8.2 = v3.8.1 演算法 + C 對齊實作 + release hygiene。音質行為與 v3.8.1 完全相同。
  • v3.8.3 = 當前 release。Preset rebalance：MILD 變成「最少動」極輕版，SOFT 接手 v3.8.2 MILD 的位置。只動 RES 參數，演算法路徑不變。
v2.0
Multi-ERLE + ENR 重構

引入雙重 ERLE 估計器（per-bin + fullband 交叉驗證），打破傳統單一 ERLE 的循環依賴問題。重構 ENR 增益門控，DT 期間語音保留大幅改善。

v2.1
AEC3-style 雙模切換 + P-floor

收斂後用 filter 精確估計；未收斂用 render-based 保守估計。P-floor 防止 Kalman 增益在長時間收斂後崩潰導致 echo path 突變後無法重收斂。

v2.3
三線驅動 effective_dt + 5 個 Blindspot 修復

加入能量 DT 訊號 + Shadow DTD，三個 DT 指標取最大值驅動全部 5 條 DT 保護路徑。同時修復 GCC-PHAT PAR gate、S_ee decay 同步、EPC render-forced 延長等。DT deg +0.06。

v2.4
動態 ERL + FilterErle 修正

動態追蹤 ERL（回音損耗）取代硬編碼 4× 上限，高耦合場景不再誤觸 DT 保護。修復 FilterErle DT 期間步長反向加速的 bug，架構更穩健。

v2.5
C/Python 全面對齊 + DT soft gate 優化

系統性比對 C 與 Python 7 處差異並修正（ENR threshold 公式、ERLE 平滑輸入、render gate 條件等）。DT per-bin 指數對 mid-DT 更溫和。C/Python Kalman 精度對齊，bare Kalman 相關性 0.99+。

v2.7
突破 Pareto — Min-statistics noise floor + CNG 預設開啟

ResFilter 動態 noise-floor gain 取代固定 g_min，小聲語音只要高於統計底噪就被保留。CNG 預設開啟填補靜音段 dead air。FS echo +0.092、DT deg +0.102 同時上升（首次突破 Pareto 限制）。

v2.8
Linear AEC 失敗場景 aggressive mode + Movement DT 系統性排查

偵測 linear filter 無法收斂的 FS tail cases（ERL > 1.2），強制進入 aggressive 壓制（FS echo +0.010）。完成 movement DT 三輪 ablation，確認 DT gate 抑制 adaptation 是根本瓶頸。

v3.0
Phase ι 多軸並進改造

同時放寬 DT mu scale 上限、shadow filter 切到 KX-blended P-update、EPC reset 邏輯收緊。之後所有實驗都從 v3.0 baseline 比較。

v3.4
Adaptive ERL hardening + Q-floor 探索

修正 ERL 上下限漂移、收斂後 Kalman Q 過小造成 EPC 後恢復慢。FS echo 提升 ~0.05。

v3.8.1 ★
Python 演算法定版（current production audio behavior）

Multi-statistics noise floor、ENR threshold 微調、CNG shaping 改進，全部凍結。BALANCED 4.006 NE deg 為當前 binding floor。R10–R16 多輪 stop-at-Phase 0 確認此版以分數論已達 plateau。

v3.8.2
C parity 實作 + release hygiene

v3.8.1 演算法移植到 C，bit-identical 驗證。新增 static-memory API 支援嵌入式（無 heap）部署。文件、版號、測試結構全面整理。音質與 v3.8.1 相同，無 audio behavior 變化。

9. 使用限制與調整建議

分三類：(A) 解不掉的硬限制、(B) 可調的參數、(C) 整合時最常踩的雷。

9.A 演算法本身的硬限制

場景行為原因 / 解法
冷啟動前 0.5–2 秒 ⚠️ 回音殘留較多 Filter 需要遠端訊號才能收斂，期間走保守 render-based 估計。應用層可在 warm-up 期間 mute 或播 "connecting…" 提示音。
DT-from-frame-0（一開始就雙說） ⚠️ 收斂困難 / 殘留長 近端從第 0 sample 就講話 → DT 保護自始至終抑制 adaptation，filter 學不起來。屬於演算法 plateau，非 tuning 可解。建議產品流程設計上避免（例如先讓對方先 hello）。
設備快速移動 / 翻轉 ⚠️ 短暫 200 ms 漏音 Echo path 突變 → EPC 偵測後 ~200 ms 重新收斂。頻繁移動 → --filter-length-ms 100 加大 model capacity。
穩態遠端（風扇 / 白噪）+ 弱語音 ⚠️ 部分弱語音段被抑制 整體語音保留率仍 ~48 %；弱起手 100 ms 段可能掉。降到 --preset mild 改善。
Speaker 嚴重飽和 / 失真（非線性） ℹ️ 殘留無法完全消除 線性 filter 無法建模非線性失真；RES 可部分壓制。嚴重失真建議搭配 NN 後處理或硬體降低 speaker 失真。
立體聲 / 多 mic 輸入 ❌ 不支援 目前僅支援 single mic + single ref。需要 stereo / multi-mic AEC 須使用其他演算法。
32 kHz 取樣率 ❌ 不支援 僅支援 8 / 16 / 48 kHz。32 kHz / 24 kHz 需外部 resample 後再進。
負延遲（mic 早於 ref 進） ❌ 不支援 必須 mic 落後 ref（正延遲）。負延遲場景須上游對齊。

9.B 可調參數對應的調整建議

遇到的問題調整方法代價
FS 殘餘回音太大 ① 先 --no-res 確認 ref 正確、延遲對齊正常 → ② --preset aggressive 或 maximum → ③ --filter-length-ms 100 aggressive/maximum 會犧牲 DT 語音保留；filter 加長 → 記憶體 +50%
DT 期間近端被壓掉 / 斷斷續續 --preset balanced → mild（不要動個別 RES knob，preset 是 co-tuned） FS echo 壓制變弱 0.3–0.5 分
第一秒回音漏出 應用層在連線最初 0.5–1 s 靜音輸出，避免暴露 cold-start residual 使用者體感上多 0.5 s 等待
裝置移動後回音 spike 正常行為（EPC 重收斂約 200 ms）。頻繁移動 → 加長 filter 記憶體上升
輸出聽起來太空 / dead-air 啟用 CNG（CLI: --cng；API: cfg.enable_cng=1） 輕微 NE deg 下降 ~0.005
離線批次處理 / 已對齊 wav --no-delay-est 關閉延遲估計，避免冷啟動 ~300 ms 的 reset 遠端 / 近端必須事先對齊好
想單獨聽 linear-AEC 殘餘來判斷問題 --no-res 跳過後濾波器 輸出保留所有未壓制殘餘 → 純做 debug 用

9.C 整合時最常踩的雷（會直接造成功能失效）

錯誤後果正確做法
Ref 餵錯訊號（不是真正進到 speaker 的 loopback） ❌ 完全失效 Ref 必須是 playback loopback（含應用層音量控制後的訊號）。常見錯誤：直接餵原始通話對方 codec 解碼輸出。
Mic / ref SR 不一致或 drift ❌ ERLE 崩 / 殘留高 兩路必須同 SR、time-aligned 啟動。SR drift > 50 ppm 會讓 filter 永遠收斂不了。
Mic / ref 延遲超過 filter_length ❌ 模型完全 cover 不到 線上延遲估計 (--max-delay-ms 250) 可處理 250 ms 內。超過必須上游補償，或加大 filter。
非 hop_size 整數倍餵資料 ❌ assertion fail aec_process 必須剛好 160 samples（@16k）。上游用 ring buffer 緩衝。
批次處理沒呼叫 aec_reset ⚠️ DT/EPC state 跨檔污染 每處理新檔前呼叫 aec_reset，確保 detector 狀態重置。
輸出再過一層 CNG / NS ⚠️ 噪聲底被雙重 shape，產生 tonal artifacts CNG 只啟用一次。若已 enable_cng=1，不要在後級再加。
多 thread 共用同一個 Aec instance ❌ race / state corruption 每個 instance single-threaded。Multi-stream → 每路獨立 instance，不共享 state。
編譯時沒用 -ffp-contract=off ⚠️ FMA contraction 造成 detector 行為不一致 必加。-O2 預設會做 FMA contraction，會破壞 HPF / saturation / detector accumulator 的位元精度。

10. Debug 模式 — 內部狀態觀察

調 AEC 最痛苦的事是「東西不對但不知道哪裡不對」。Debug 模式提供 per-frame 內部狀態 dump，讓你立刻看到 filter 收斂到哪、DT 偵測為何觸發、ERLE 走勢、為什麼 RES 在這一幀放這個 gain。

10.1 兩種 debug 介面

Python (研發 / 演算法調整)C (release / 嵌入式驗證)
啟用方式aec.get_stats() 或 AecDebugLogger編譯時 -DAEC_DEBUG，執行時 --debug-level 2
輸出格式AecStats dataclass，30+ 欄位Stderr 或檔案；timestamped key=value
頻率每幀（10 ms）皆可呼叫每幀，含模組 tag
Release builds—-DNDEBUG 完全 strip log strings + assertions

10.5 怎麼用 debug log 解問題

觀察到的徵兆看哪些欄位對應問題
10 秒後 ERLE 還是個位數filter_state 一直 WARMUP/ADAPTING、far_power_db 太低遠端能量不足、ref 接錯訊號、SR drift
近端被切掉dt_confidence 卡在 1.0、dt_from_energy 異常高ERL 估計錯、preset 太激進
echo 突然爆出來epc_active=Y、shadow_advantage 飆高EPC 觸發中，正常 200 ms 恢復
輸出過度死寂res_gain_mean_db < −30 dBRES 過壓 → 降 preset 或開 CNG
輸出 ERLE 高但聽起來像鳥叫res_gain_mean_db 跳動劇烈ENR sigmoid 太硬 → preset 改 mild
EPC 反覆觸發epc_active 在 Y/N 間跳SR drift / 延遲不穩 / 環境突變過頻繁
