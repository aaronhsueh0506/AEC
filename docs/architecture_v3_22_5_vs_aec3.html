v3.22.5 — core architecture (AEC3-aligned _aec3_post)

Current shipped · __version__ = 3.22.5 · core pipeline unchanged since v3.21 (2026-05-19); the v3.22 policy layer is detailed below this flowchart

Three Pareto presets (gentle/balanced/aggressive, balanced = production) differing only in the far-active min-gain floor. Reference-path HPF retired (mic-only). AEC3-aligned _aec3_post chain (StationarityEstimator + AecState + ResidualEchoEstimator + SuppressionGain + comfort noise + OLA) — the legacy 9-stage ResFilter is retired. C port bit-exact.

✓ What the current AEC3-aligned pipeline ships

  • AEC3-aligned _aec3_post chain (StationarityEstimator + AecState + ResidualEchoEstimator + SuppressionGain + CNG + OLA) — the legacy 9-stage ResFilter is retired. DT/NE deg beats the AEC3 reference by ≥ 0.33 / 0.59.
  • Three Pareto presets (gentle/balanced/aggressive) on a single far-active min-gain-floor knob — no co-tuning trap (the old 40-knob 5-preset menu was deleted).
  • AEC3-aligned delay subsystem — matched filter + lag aggregator + clock-drift detector + render-delay controller (replaces GCC-PHAT).
  • RenderSignalAnalyzer — per-bin tonal mask + poor_signal_excitation freezes the refined filter on bad render frames (fixes E0l0 / wJVP class NE outliers).
  • AecState ADT over 12 sub-analyzers → multi-gate usable_linear_estimate replaces the brittle 10-frame ERLE latch.
  • Sub-band ERLE drives SuppressionGain ERLE-divide refinement, AEC3-style.
  • ReverbModel — per-bin tail across the impulse response (decay + frequency response), replacing the one-tap exponential.
  • Shadow filter is NLMS (PBFDAF) — AEC3 coarse-filter role; faster tracker that survives echo path changes.
  • FilterMisadjustmentEstimator + ScaleFilter — long-term echo/error drift triggers W rescale.
  • v3.22 post-filter policy layer — split min-gain floor + per-bin near-end protection (detailed below the AEC3 reference).
  • C port bit-exact (peak |Δ|=0) — the C aec3_post mirrors the Python chain.

⚠ Known limitations / gaps

  • TransparentMode disabled. Our AecStateConfig.enable_transparent_mode = False: requires AEC3's SubtractorOutputAnalyzer to feed a per-frame any_filter_converged pulse; legacy FilterConvergenceAnalyzer stays at False on hard cases like 9xjhi, so TM would falsely activate after ~6 s of strong render and kill usable_linear. Port pending. TODO
  • OLA algorithmic delay. The AEC3 chain has a ~64-sample (4 ms) algorithmic delay from sqrt-Hann OLA, lag-corrected at the output limiter; consumers downstream of aec.process() should be aware of the per-frame latency. documented
  • No dedicated non-linear echo model. Loudspeaker distortion is the remaining FS/DT ceiling (v3.13 E5 closure); a Volterra / HDRES arc is designed but not implemented — confirmed Pareto-bound for now.
  • NN swap not in the AEC core. The DSP chain is production / fallback; an echo-aware joint NR+RES already runs in the Audio_ALG integration repo (folds R² into NR's noise floor), and each freq block is NN-swappable via AecResContext — but the AEC core itself stays DSP-only.
  • Legacy FilterConvergenceAnalyzer still wired. AecState uses the AEC3-aligned multi-gate, but the legacy 10-frame ERLE latch object is still maintained on self._convergence for backward-compat property reads.

WebRTC AEC3 — reference

Chromium modules/audio_processing/aec3/

No preset menu — single EchoCanceller3Config struct with Field-Trial overrides. The canonical reference our _aec3_post chain mirrors.

⚠ Known issues / quirks in WebRTC AEC3 itself

  • TransparentMode false-activation. After ~6 s of strong render with no near-end speech, the SubtractorOutputAnalyzer / FilterAnalyzer combo declares the room transparent and the suppressor passes mic through — even when echo is still present. Documented inside the C++ code (aec_state.cc comments); WebRTC ships it default-ON anyway because it helps the common Chromium use-case. Our build disables it (see the limitations card above).
  • Strict refined-filter convergence detector. FilterAnalyzer::Update requires 10 consecutive blocks > 5 dB ERLE to assert consistent_estimate. On hard cases (deep DT or low-coupling rooms with reverb), this never asserts → AecState's downstream gates are stuck in their fallback paths. Known WebRTC limitation, no upstream fix.
  • Sub-band ERLE EMA can lock high during heavy DT. The asymmetric EMA biases towards higher ERLE; in heavy DT segments the per-band ERLE estimate stays optimistic and SuppressionGain over-suppresses NE.
  • Reverb decay estimator is loosely identified. The decay coefficient comes from a one-tap fit to echo_path_estimate tail; real rooms have multi-rate decay (early reflections vs late tail) that the model collapses.
  • OLA in suppression_filter.cc is mathematically clean. kFftLength=128, hop=64 (kFftLengthBy2), sqrt-Hanning analysis × sqrt-Hanning synthesis = Hann at 50 % overlap → sum-to-one reconstruction. Standard textbook setup — no known OLA-specific defect. The 64-sample (4 ms) algorithmic delay it introduces is inherent to the design, not a bug.
  • Coarse filter (NLMS shadow) has no gain control. μ is fixed at 0.5 (kCoarseFilterStepSize). On near-end-heavy frames the coarse filter can drift faster than the refined filter; AEC3 mitigates with poor_coarse_filter_counter but the trigger is conservative.
  • EchoPathChange detection is energy-based. EchoPathChangeDetector looks at far-energy step changes; can't distinguish a real path change from a microphone gain change (handset → speakerphone). Mostly benign because the response is the same (filter reset) but the event log conflates them.
  • EchoCanceller3Config is a 150-field struct. Field-Trial overrides spread across Chromium make production tuning hard to audit; no preset menu (unlike our pre-v3.21 design — though we just retired ours too).

v3.22.5 vs WebRTC AEC3 — current alignment + remaining gaps

v3.22.5 ships an AEC3-aligned but not bit-equal port. Same block-level structure, mostly the same algorithm, but several detail choices differ. The closer this list gets to empty, the closer we are to a 1:1 port. (On AECMOS we deliberately sit at a different Pareto point — less echo than AEC3, but beating it on every degradation axis; see the score panel.)

✓ Already aligned with AEC3

  • Block / FFT / hop rates (64 / 128 / 64).
  • Refined Kalman filter + NLMS coarse-filter pairing.
  • EchoPathDelayEstimator — matched filter + lag aggregator + clock-drift.
  • RenderSignalAnalyzer — narrowband tonal mask + poor_signal_excitation.
  • AecState ADT seam over sub-analyzers (we have 12, AEC3 has 11 — close).
  • ResidualEchoEstimator linear / render-based 2-path + ReverbModel tail.
  • SuppressionGain Wiener + over-estimation.
  • ComfortNoiseGenerator = per-bin PSD EMA × sqrt(1 − G²).
  • SuppressionFilter OLA with sqrt-Hann analysis × sqrt-Hann synthesis.
  • StationarityEstimator + FilterAnalyzer + FilteringQualityAnalyzer.

⚠ Where we still differ from AEC3

  • No TransparentMode. AEC3 has it (default ON in Chromium); we disabled because we lack SubtractorOutputAnalyzer — see future work below.
  • No NearendDetector. AEC3's subband NE detector feeds SuppressionGain mode switching; our v3.18 D.1 substrate closed CANNOT-SHIP, so we don't have an equivalent live consumer.
  • No EchoAudibility module. AEC3 computes per-bin audibility from JND-weighted PSD ratios; we use a simpler spectral floor.
  • SuppressionGain over-estimation differs. AEC3 has a four-mode HighFrequencySuppressionConfig + DominantNearendConfig with mode-switched coefficients; ours has a smaller subset and the high-frequency mode tuning is not fully aligned.
  • Reverb decay estimator is partial. We have ReverbDecayEstimator + ReverbFrequencyResponse but the estimation gate is simpler than AEC3's adaptive tail-length controller.
  • FilterMisadjustmentEstimator is ours. AEC3 has a different ScaleFilter design (per-block scale ratios); we use a single fullband ratio with asymmetric EMA. Same goal, different math.
  • PathChangeRegimeHandler is ours. AEC3 handles echo-path-change via Subtractor::HandleEchoPathChange + AecState's full_reset cascade. Our regime handler bundles those decisions with shadow-copy logic that AEC3 doesn't have.
  • Coarse-filter step size. AEC3 uses 0.5; we expose shadow_mu_nlms defaulting to 0.5 but our coarse-filter freeze logic (poor_coarse_filter_counter) is partial.

→ AEC3-alignment port targets (would shrink the diff)

Note: the shipped v3.22 line did not pursue these AEC3 ports — it took the orthogonal post-filter policy route instead (split min-gain floor + per-bin near-end protection + delay-acquire guard, see the v3.22 policy section below). These remain open AEC3-alignment targets.

  • Port SubtractorOutputAnalyzer → enable TransparentMode safely on hard cases like 9xjhi. Highest priority — currently disabled gate caps DT/NE on a small but visible tail of cases. open
  • Port NearendDetector + mode-switched SuppressionGain. Pair with retry of the v3.18 D.1 subband-NE substrate that closed CANNOT-SHIP — the new wiring goes through SuppressionGain directly instead of ResFilter. v3.22
  • Port EchoAudibility. JND-weighted per-bin gain floor; should improve NE-heavy buckets without echo regression. v3.22
  • Align SuppressionGain over-estimation. Bring the 4-mode HighFrequency + DominantNearend tuning into our suppression_gain.py. v3.22
  • Mirror ScaleFilter exactly. Per-block scale ratios + AEC3 stability gate; retire our asymmetric-EMA version. v3.22+

→ Future arcs (beyond AEC3 alignment)

  • C port catch-up — DONE. The C c_impl/ now mirrors the Python AEC3 chain (aec3_post + state/residual/delay) and is bit-exact (peak |Δ|=0). resolved v3.22.5
  • Volterra / HDRES non-linear residual. Primary lever for the remaining FS / DT echo ceiling (loudspeaker non-linearity); designed but confirmed Pareto-bound on the current corpus. Multi-month arc. v3.23+
  • NN swaps via AecResContext. An echo-aware joint NR+RES already runs in the Audio_ALG integration repo; each freq block (residual / NR / joint) is NN-swappable on the shared 257-bin grid. The AEC core stays DSP-only / fallback. integration arc
  • Pruning of FilterConvergenceAnalyzer legacy seam. AecState's multi-gate replaces it; the legacy object is still wired for backward-compat property reads.
  • Audit / retire p52_regime_classifier.py. Only consumed by test_p52_regime.py; if the regime trace isn't needed for production, drop both.

v3.22 post-filter policy layer (inside current v3.22.5)

Shipped across v3.22.0 → v3.22.5 · current __version__ = 3.22.5 (byte-equal since 3.22.4)

v3.22 is built on top of the v3.21 core — the pipeline above is unchanged (HPF → Saturation → DelayEst → PBFDKF + shadow PBFDAF → AEC3-post = StationarityEstimator + AecState + ResidualEchoEstimator + SuppressionGain + CNG + OLA). v3.22 did not restructure the architecture; it added a post-filter policy layer (frequency-selective near-end protection + split min-gain floor) plus a stack of default-ON bug fixes / coordinate-consistency corrections. The changes below all live inside the SuppressionGain / ResidualEchoEstimator / ERLE blocks and the delay-acquire guard.

v3.22.0 — split min-gain floor + default-ON correction stack

  • Split min-gain floor (far-active vs far-silent), default ON. The single broadband suppression-gain floor is split into two operating points keyed on far-end activity → caps DT near-end over-suppression without giving up FS echo depth. This is the core v3.22 policy lever.
  • E1 — ERLE coordinate consistency. Y²/E² windowed capture aligned so the ERLE numerator/denominator share the same time-domain capture coordinate (fixes a frame-skew that under-credited the linear filter).
  • erle_render_x2_psd_scale — reverb-model revival. Restores the missing _PSD_SCALE on _x2_reverb_for_erle so the reverb model contributes to ERLE instead of being silently dead.
  • E2 — raw-capture output base. When the linear estimate is unusable, the output base falls back to the raw capture (instead of a degenerate residual) → removes the cold-start / non-converged X² wipe artifact.
  • D3 — soft near-end tuning blend. Sigmoid ENR-driven blend that softens the near-end vs echo gain decision instead of a hard switch.
  • L1 — Kuech–Kellermann 2nd-order nonlinear residual. Adds a 2nd-order nonlinear term to the residual echo estimate (loudspeaker non-linearity), feeding ResidualEchoEstimator.
  • C′ — coherence ERLE gate. Coherence-based gate on the ERLE update path.

v3.22.1 — delay-acquire phantom-mislock guard

  • delay_acquire_protect_converged, default ON. Rejects a spurious late first delay-acquisition when the filter is already cancelling — i.e. when a phantom late lag would otherwise displace a good converged alignment. Lives in the EchoPathDelayEstimator acquire path; no change to the steady-state tracker.

v3.22.2 — per-bin near-end blend + deeper far-active floor (current BALANCED)

  • soft_nearend_blend_per_bin, default ON. The D3 near-end tuning blend goes frequency-selective (per-bin) instead of broadband. Near-end protection now applies only in the bins that carry near-end speech.
  • far-active min-gain floor lowered −22 → −28 dB. Because the per-bin blend isolates near-end protection, the deeper far-active floor can suppress more echo without the broadband DT near-end cost the deeper floor would otherwise have caused. This is the v3.22.2 net win: more echo cancellation at no DT-deg penalty.

What stayed exactly the same as the v3.21 core

  • Front-end (HPF mic-only, Saturation, EchoPathDelayEstimator) — unchanged.
  • Linear filter (PBFDKF refined + shadow PBFDAF/NLMS + PathChangeRegimeHandler) — unchanged.
  • AEC3-post block topology (StationarityEstimator → AecState → ResidualEchoEstimator → SuppressionGain → CNG → OLA) — unchanged; v3.22 tunes the policy inside these blocks, not their wiring.
  • _ours_nores.wav bypass tap; byte-equal regression harness — unchanged. (The three presets share this exact pipeline; they differ only in the far-active min-gain floor.)
